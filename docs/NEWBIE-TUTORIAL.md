# AegisBank 新手教程（第一次使用）

> 面向第一次打开 AegisBank 控制台的人：不需要看 API 文档、不需要懂代码，按本文顺序操作即可。
> 本教程对应提交：阶段 2A（六项硬要求）完成之后；所需演示数据由 `bash scripts/seed-demo.sh` 植入。

---

## 0. 打开你会看到什么

浏览器打开 **<http://127.0.0.1:5173>** 后，你会看到：

- 顶部：品牌 AegisBank、**系统就绪横幅**（SQLite / 审计链 / 模拟银行种子 / Planner 四个组件都是 OK 才能做写操作）、**角色切换**（USER / OPERATOR / AUDITOR）。
- 左侧导航共 7 个页签：

| 编号 | 页签 | 你可以做什么 |
|---|---|---|
| 01 | 银行概览 | 看账户、卡片、订阅与今日累计转账；确认虚拟卡 `**** 9001` 与 3000 元在不在 |
| 02 | 六场景面板 | 理财、联系人、账单报告与异常、订阅续费、卡片申请、定时任务 + 时间快进 |
| 03 | 任务控制台 | **最主要入口**：用自然语言发起任务、看计划、确认、看执行回执与步骤日志/回滚 |
| 04 | 权限控制台 | 按工具撤回/恢复授权；看每个工具「可撤销 / 不可撤销 / 只读」 |
| 05 | 2A 能力 | MFA 验证方式、工具沙箱演示、IM 渠道发消息 |
| 06 | 运维面板 | 熔断状态、触发原因、事件、operator 一键解锁 |
| 07 | 操作审计 | 哈希链校验、证据分层、2A 事件（补偿/MFA 失败/沙箱/撤权） |

> 演示固定用户是 `demo-user`，没有登录页；角色切换是**演示用**请求头，不是真实认证。所有金融数据都是模拟数据。

## 2. 五分钟快速上手（7 步）

> 每一步都按「点哪里 → 输入什么 → 看到什么」写。红色操作会要求验证码：**演示 OTP 固定 `246810`**；也支持模拟生物识别 **`FACE-888888`**。

### 第 1 步：确认虚拟卡（01 银行概览）
1. 打开「01 银行概览」。
2. 在「银行账户」里找到 **虚拟卡账户（ACC-3003）**，余额 **3000.00**；在「卡片状态」里找到 **`**** 9001`**。
3. 顺便留意：异常订阅 `SUB-3002` 的提示、今日累计转账与 1000 元红色阈值。

### 第 2 步：查账单（绿色，直接执行）
1. 切到「03 任务控制台」，在输入框输入：`查询我的本月账单`，点「交给 Agent」。
2. 预期：**绿色**直接完成，回执里列出总支出、分类、异常交易、可疑订阅 ID。

### 第 3 步：用虚拟卡转账（黄色确认）
1. 输入：`从 ACC-3003 向 ACC-2002 转账 500 元`。
2. 预期：**黄色**，弹出确认窗口，显示计划、风险原因、ActionEnvelope 摘要。
3. 点「确认执行」。
4. 回执成功后回到「01 银行概览」：虚拟卡账户余额变成 **2500.00**，并新增一条转账流水。

### 第 4 步：同日再转，体验红色强验证
1. 输入：`从 ACC-3003 向 ACC-2002 转账 600 元`。
2. 预期：**红色**——因为今日累计将达 1100 元，超过 1000 元阈值。
3. 在确认窗口选择验证方式 `otp`，输入 **246810**（或选 `biometric` 输入 **FACE-888888**），点「验证并执行」。
4. 余额变成 **1900.00**；「07 操作审计」里能看到这次确认与 MFA 结果。

### 第 5 步：卡片管理（红色）
1. 输入：`挂失 CARD-9001` → 红色确认（OTP / 生物识别）→ 执行。
2. 「01 银行概览」中该卡状态变为挂失/异常。
3. 再输入：`解挂 CARD-9001` → 红色确认 → 恢复。

### 第 6 步：权限撤权与阻断（安全机制）
1. 到「04 权限控制台」，搜索 `transfer`，点「撤回」。
2. 回到「03 任务控制台」再输入一次：`从 ACC-3003 向 ACC-2002 转账 100 元`。
3. 预期：任务被**阻断**，原因显示「未授权 / 请先在权限控制台开启」。这证明写操作真的经过统一网关。
4. 操作完记得回 04 重新「授予」。

### 第 7 步：看审计（可验证、不可篡改）
1. 打开「07 操作审计」，可看到刚才所有执行、确认、MFA、补偿等事件。
2. 顶部哈希链状态应为「校验通过」；展开一条记录能看到**证据分层**（Mock 数据 / 人工确认 / 策略判断 / 审计链）。

## 3. 风险分级怎么看

| 颜色 | 含义 | 系统行为 | 例子 |
|---|---|---|---|
| 🟢 绿色 | 只读查询 | 满足最小权限后直接执行 | 查账单、查余额、看理财持仓 |
| 🟡 黄色 | 会修改账户/订阅/持仓设置 | 5 分钟内轻量确认一次 | 小额转账、改还款日、取消订阅、小额赎回 |
| 🔴 红色 | 资金变动或账户安全 | 必须二次身份校验（OTP / 生物识别） | 大额或累计超 1000 元转账、挂失/解挂、密码重置、理财申购 |

看点：确认窗口里会写清「为什么是黄色/红色」（风险引擎给的原因），以及具体执行参数——**你确认的就是这一笔**（计划哈希 + 参数哈希 + nonce + 过期时间绑定）。

## 4. 六个业务场景速查（在 03 任务控制台输入）

| 想做什么 | 输入示例 | 预期 |
|---|---|---|
| 查账单 | `查询我的本月账单` | 绿色，分类 + 异常订阅 |
| 账单清理联动 | `分析我的账单并取消异常订阅` | 两步 DAG（先分析再取消），黄色确认 |
| 转账 | `从 ACC-3003 向 ACC-2002 转账 500 元` | 黄色确认 |
| 给联系人转账 | `给妈妈转 500` | 识别联系人，黄色确认 |
| AA 拆分 | `和妈妈、张三 AA 300` | 生成 2 笔各 100 元转账（并行 DAG），确认后执行 |
| 理财申购 | `买 1000 元稳健短债A` | 红色（资金投入），确认 + OTP |
| 理财赎回 | `赎回 500 元` | 黄色；超过 1000 元变红色 |
| 卡片：虚拟卡 | `申请虚拟卡` | 两步 DAG：申请 → 审核发卡，黄色确认 |
| 卡片：改额度 | `把信用卡额度调整到 8000 元` | 红色 |
| 定时转账 | `下周三给张三转 500` | 创建定时任务，黄色确认 |
| 生日联动 | `帮我准备下个月妈妈的生日，预算 1000 元` | 4 步 DAG：查生日 → 锁预算 → 订花 → 订蛋糕 |
| 订阅 | `我的订阅还有哪些要续费` | 绿色，返回续费提醒 |
| 理财持仓 | `我的理财持仓` | 绿色 |

> 说不清金额/对象时，系统会给**澄清提示**（不会瞎猜）。例如只说「我要转账」，会问你补充收款账户和金额。

## 5. 02 六场景面板（不用打字也能操作）

- **理财**：5 只 R1–R5 模拟产品、持仓、订单；页面显著标注「模拟数据，不构成投资建议」。
- **联系人**：妈妈的别名/手机号/生日等（脱敏展示）。
- **账单**：月报/年报切换，分类条形、Top 商户、环比、预算超支、异常检测（4 条确定性规则）。
- **订阅**：扣费实体识别 + 未登记代扣 + 续费提醒（days_left）。
- **卡片**：申请状态（applying / issued）。
- **自动化**：定时任务、预算目标、礼物订单，点「**时间快进**」可执行到期任务（到期转账/礼物下单），执行会写审计（`trigger_source=scheduled`）。

## 6. 2A 进阶演示（可选，答辩 / 深度体验用）

1. **换角色**：顶栏切到 `OPERATOR` 或 `AUDITOR`。
   - OPERATOR：不能发起银行任务（会明确提示无 `tool:execute`），但可以进「06 运维面板」解锁熔断。
   - AUDITOR：只能看审计与信任信息，无法改权限、无法发起任务。
2. **MFA 两种方式**：红色确认弹窗里选 `otp`（246810）或 `biometric`（FACE-888888）；「05 2A 能力」可看 providers 与策略。
3. **沙箱演示**：05 页分别点 `network / slow / oversize`，会看到被沙箱拦截并写审计（`sandbox_blocked` / `sandbox_timeout`）。
4. **IM 渠道**：05 页填文本消息（可填 `message_id` 保证幂等），回执里带确认话术；也可以直接发 `确认 {action_id} 验证码 246810`。
5. **回滚/补偿**：在任务回执的「步骤日志」里可对已执行动作发起回滚；多步 DAG 中途失败会自动逆序补偿，结果状态 `rolled_back`（全成功）或 `unknown`（部分失败，需人工对账）。
6. **熔断**：连续失败/短时多次红色/注入累计会触发熔断，写操作被拒；operator 在 06 页解锁（审计留痕）。

## 7. 常见问题

**Q1：页面能开但所有按钮是灰的？**
看顶部就绪横幅：不是 `ready` 时写操作被强制禁用（fail closed）。通常是后端没启动或数据库不可用，确认 <http://127.0.0.1:8000/api/health/ready> 返回 `ready`。

**Q2：`5173` 打不开？**
先试 <http://localhost:5173>；确认前端进程在跑（`pnpm dev` 的输出里有 `Local: http://localhost:5173/`）。WSL 端口转发正常时 Windows 浏览器可直接访问 `127.0.0.1`。

**Q3：我想换个干净的演示环境？**
停后端 → `bash scripts/seed-demo.sh` → 启动后端（指向 `data/dogfood.db`）→ 刷新页面。

**Q4：红色操作为什么必须输验证码？**
红色代表资金变动或账户安全操作。系统用 `ActionEnvelope` 把「你确认的那一笔」绑定起来，执行前还会重新校验权限、风险与 nonce，防止「确认后被偷改」。

**Q5：操作失败/结果不明怎么办？**
看任务回执的 `status` 与「步骤日志」：
- `unknown`：结果不确定，系统**不会**自动重试，需人工对账或回滚；
- `blocked`：被网关/熔断/就绪状态拒绝，看 `reason`；
- 补偿失败同样会显式暴露，不会假装成功。

**Q6：这些是真实银行数据吗？**
不是。全部来自 Mock Bank Core 的 SQLite 模拟数据，不连接真实银行、不产生真实资金；理财内容不构成投资建议。演示 OTP（246810）与生物识别 token（FACE-888888）仅用于本地演示。

**Q7：能看接口/自己调吗？**
<http://127.0.0.1:8000/docs> 是 FastAPI 自动文档；所有 UI 操作都等价于 `/api` 调用，且与审计、权限、风险完全一致。

## 8. 发现问题怎么反馈（阶段 2.5）

把体验问题按下面格式发出来，会记录进 `docs/UX-RECORD.md` 并修复：

```
编号：UX-001（可留空）
场景：转账
严重度：P0 阻断 / P1 严重 / P2 一般 / P3 建议
用户目标：我想……
实际发生：我看到……
预期行为：我希望……
证据：截图或操作步骤
```

优先级：P0（阻断主流程）→ P1（误解风险/无法恢复）→ P2（体验粗糙）→ P3（建议）。
