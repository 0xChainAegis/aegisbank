# 自然语言能力后续待办

本文件将现有核验结论整理为可独立验收的后续任务。2026-10-27 已实现 P1 有界候选契约与校验；原定未见表达泛化验收仍待完成，详见 [P1 报告](NLP-P1-2026-10-27.md)。建议先完成单意图语义草稿、口语同义表达与参数来源，再扩展有边界的续问和组合规划。

## 当前基线

- **P0 已实现**：完整金额词元规范化、Decimal 分位校验、金额原文与位置记录；已识别的条件、组合和参数冲突转澄清；rule / llm / auto / 显式工具入口共用检查；订阅事实不可用时不再猜选演示目标。P0 是有界规则防线，不能证明识别了任意自然语言的所有条件和子任务。
- **P1 有界实现已落地，泛化验收未完成；P2–P4 尚未实现**：已提供 SemanticFrame/v1 与本地来源校验；没有通用会话记忆与纠错、任意条件与组合规划、完整理解摘要和正式 NLP 保留集评测。已有 DAG、受限续问、金额来源 assumptions 和前端恢复能力不能替代这些阶段。
- 默认 Planner 为 `rule`，另有 `llm / auto`。关闭语义模块时的旧 LLM 候选仍受规则参考计划约束；P1 模式改用场景可信模板、原文槽位与工具序列的一致性校验，不能为了增加表达覆盖直接删除这些保护。
- 现有澄清续问绑定用户与角色，10 分钟有效、单次消费，以原指令加补充文本重新规划；修改或取消类补充要求重新提供完整指令。这不是任意上下文理解。
- 原 NLP 评估文档中的前端 **53 项**是 P0 当时的历史快照；[本轮前端验收记录](FRONTEND-REPAIR-2026-10-25.md)记载 **73 项通过、8 个文件**。这些是工程回归数量，不是语言理解准确率；后续变更需重新验收，不能沿用旧数量。
- “保留集支持范围内完整计划语义正确率 ≥95%”仅为[原评估建议](NLP-ASSESSMENT-AND-PLAN-2026-10-25.md)中的初始目标，**不是现有成绩**。本轮没有新增真实 LLM 准确率、延迟或成本测评；Mock 模型响应测试不能当作真实模型效果。

## 协作与不变约束

后端与 NLP 负责人负责语义契约、解析、参数来源校验和执行侧回归；前端负责人配合理解摘要、澄清和确认界面；调研与材料协作者维护标注、复现说明和结果口径。每个任务先由实现负责人准备可复现结果，再由其他角色核对验收，不公开个人联系方式或团队聊天。

所有任务遵守[项目规则](../AGENTS.md)和[安全设计](SECURITY.md)：Planner 只提出候选；动态风险只能保持或上调；写入继续经过统一网关、分级确认与演示 MFA、ActionEnvelope、ToolExecutor、SandboxGuard 和审计。新增事实查询也须走受控链路，不能由前端或模型构造“已验证”的银行事实。业务和测试继续使用 Mock Bank Core。

下列任务在完成验收前都保持未完成；勾选任务只表示其限定范围已通过，不代表整个阶段或通用 NLP 已完成。

## 第一批增量

### 1 定义单意图语义草稿

- [x] **目标（P1，有界契约已验收）**：先为账单查询与单笔联系人转账定义版本化语义草稿。记录意图、对象、金额或账期、缺失槽位、未覆盖片段，以及每个关键参数的原文位置、解析方式和事实来源；与现有 `ExecutionPlan` 分开。
- **验收**：同一明确输入生成可重复的候选；缺失、歧义和未支持语义均显式保留，不能静默补全或丢弃；草稿本身不触发工具执行。金额继续复用 P0 解析器，不新增第二套金额规则。
- **安全链**：草稿不是授权，不能从 `confidence` 推导权限、降级风险或绕过现有编译和确认。
- **协作**：后端与 NLP 负责人主责，前端负责人核对展示所需字段。

### 2 建立独立标注与基线

- [ ] **目标（P4 基础，可与任务 1 并行）**：为上述限定范围建立人工标注语料，标注意图、关键槽位、来源、应澄清原因和允许的动作；按语义模板或表达家族划分开发集与保留集。语料规模及各类样本数随首次基线记录，不把建议的规模写成已完成数量。
- **验收**：基线报告注明工具目录、Mock 种子、Planner 模式、代码版本和数据划分；正向可用例与安全反例同时统计。真实模型实验单独记录模型版本及配置，不能与 Mock 候选测试混合。
- **安全链**：基线首先使用计划预览和隔离临时库；如验证执行，用快照比较业务表与待确认表，允许必要审计变化，不触碰真实资金或客户数据。
- **协作**：调研与材料协作者维护标注，后端与 NLP 负责人实现评测并复核争议标签。

### 3 扩展单意图口语并校验来源

已实现开发语料中的受限表达、实体与参数来源校验；未见表达泛化未达到原验收，因此此项保持未勾选。

- [ ] **目标（P1）**：在任务 1 的契约下支持账单查询与单笔联系人转账的同义表达，例如“看看最近钱都花哪儿了”。联系人从当前用户受控事实中解析，未知或多匹配时澄清。
- **验收**：未用于开发的同义表达能产生语义等价计划；关键金额与对象精确匹配；未知对象、歧义金额、额外条件或动作不能被改写成单笔转账。与原规则基线对照，记录新增可用表达及误拒绝。
- **安全链**：保留 P0 和现有 LLM 候选检查。不能仅以“模型更聪明”为理由放开写操作种类、笔数或参数来源限制；后续迁移这些限制必须另设验收。
- **协作**：后端与 NLP 负责人主责，调研与材料协作者提供独立表达。

### 4 展示理解摘要与参数来源

- [ ] **目标（P4 的限定展示增量）**：前端展示当前语义草稿的意图、对象、金额、原文来源、未确定信息和计划步骤。先做可检查的只读草稿，不在这一步加入任意编辑、上下文继承或条件执行。
- **验收**：用户可以对照原文发现对象或金额不一致；模型候选、确定性解析、银行查询事实与执行结果区分显示。刷新、切换任务或角色后不会展示另一任务的草稿；未知字段不显示为零值或安全状态。
- **安全链**：展示草稿不代表已执行；必须继续向服务端获取有效计划与确认状态，不能信任本地缓存作为授权。
- **协作**：前端负责人主责，后端与 NLP 负责人提供字段与测试响应，材料协作者核对演示口径。

以上四项构成推荐的下一批工作。先用限定表达展示“理解得对、来源可查、需要时澄清”，不直接承诺任意上下文或条件任务。

## 后续受控扩展

### 5 支持有限缺失槽位补全

- [ ] **目标（P2）**：仅在已确定任务草稿中补全金额或明确对象，例如“给妈妈转钱 → 五百”。定义服务端草稿标识、用户与角色绑定、TTL、版本及单次消费规则。
- **验收**：正常补全、过期、跨用户、跨角色、并发回复和重复回复均有回归；只继承当前草稿中明确可用的槽位。新回答与原文冲突时说明原因，不猜测。现有受限续问的行为变化单独记录。
- **安全链**：不得继承上一笔授权或 MFA；补全后仍重新生成计划、评估风险和确认，保留幂等键及原请求恢复语义。
- **协作**：后端与 NLP 负责人主责，前端负责人实现缺失信息提示。

### 6 支持执行前纠错并使旧确认失效

- [ ] **目标（P2）**：在有版本的未执行草稿中支持“不是500，改成300”等限定修订。已执行动作不能被改写，转为新操作或受控补偿。
- **验收**：金额或对象改变生成新 `plan_hash`；旧确认不可执行新计划；重复修订不增加动作；并发版本冲突可解释。明确区分补全、修订、拒绝与已执行后撤销。
- **安全链**：新版本重新评级并取得必要确认/MFA，不能复用旧 nonce、旧批准或旧验证结论。
- **协作**：后端与 NLP 负责人主责，前端负责人配合版本变化提示。

### 7 扩展白名单组合的完整性校验

- [ ] **目标（P3）**：从已标注的完整意图列表编译有限的无条件组合，例如“分析账单 → 取消我选中的订阅 → 查询余额”，先限制动作集合和长度，不开放任意组合。
- **验收**：动作、选定对象及顺序均有对应步骤；未选择订阅时零写入；额外或未覆盖动作转澄清；否定局部写动作不会误执行该动作。比较依赖与行为等价，不只比较 JSON 字符串。
- **安全链**：各节点继续经过网关和风险复检；确认绑定整条计划。类型化上游引用必须校验，禁止 `eval`、任意模型代码和未登记工具。
- **协作**：后端与 NLP 负责人主责，前端负责人展示完整计划和未覆盖内容。

### 8 引入有限条件并验证写入时事实

- [ ] **目标（P3，依赖前述契约和完整性验收）**：只对明确的条件表达式白名单建立真、假、未知三种结果。余额等事实通过受控工具读取，写入时重新核对；并发资金条件在 Mock Bank Core 事务内保证一致性。
- **验收**：条件为假或未知时零业务写入；检查后余额变化不能让过时条件生效；条件不能被遗漏、替换或当作描述文本。中途撤权、注入、重复提交与未知执行结果不能产生额外动作。
- **安全链**：条件成立不代表授权成立，仍需完整风险、确认、Envelope、执行器和审计；未经支持的条件继续澄清。
- **协作**：后端与 NLP 负责人主责，前端负责人配合条件解释，材料协作者整理反例。

### 9 完成可复现的效果报告和演示

- [ ] **目标（P4）**：扩充独立标注与保留集，比较原规则、现有 LLM 与新方案；报告关键参数精确匹配、完整计划语义正确率、漏步骤率、条件保留率、必要和非必要澄清、多轮完成率，以及真实模型实验的延迟和成本。
- **验收**：公开定义支持范围、样本构成、分母与失败案例；保留集不用于调参，近似改写不跨集合泄漏。安全反例中的错误写执行与正向可用性同时报告，不能靠全部拒绝取得“安全”结论。95% 仅为待基线复核的候选目标，实测前不得写成成绩。
- **安全链**：演示继续使用 Mock 数据；明确模型解释、确认、执行和审计的区别。所有新增能力重跑工程回归与相应行为验收，不以旧版通过数字代替当前验证。
- **协作**：调研与材料协作者整理报告，后端与 NLP 负责人对结果负责，前端负责人配合可复现演示。

## README 和答辩表述检查

- 可以表述为“支持限定表达、部分口语、受限续问和预置跨场景 DAG 的可信银行智能体原型”。六场景工具链路覆盖不等于所有表达、所有子业务或生产流程完整覆盖。
- 不宣称自由自然语言理解、任意复杂任务、多轮记忆纠错、通用条件规划、95% 准确率、真实银行接入或生产级 MFA/沙箱已经完成。
- **账单分析到取消订阅当前先确认整条 DAG**：调度器发现任一节点需确认时，先保存并返回整个待确认计划；确认通过后才按依赖执行节点。不要写成“账单节点已先自动执行，再只确认取消节点”。独立的绿色查询仍可自动执行。
- “复杂任务会拆解为 DAG”应限定为“已支持的预置复杂任务”。条件和任意组合在当前支持范围之外时保守澄清，不应被演示成已执行。
- 展示金额来源 assumptions 不等于完成每个槽位的来源契约；前端可靠性修复不等于 P4 NLP 效果评测完成。
- 区分历史快照、当前工程回归与未来指标目标。任何测试数量、准确率、延迟或成本都附对应版本及测量条件。
