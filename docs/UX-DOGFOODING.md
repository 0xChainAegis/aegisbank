# 开发者人工用户体验（Dogfooding）清单

## 1. 目的

开发者和评委看到的是不同东西：

- 开发者知道 API、状态机、字段和演示数据；
- 用户只知道我想完成一笔业务。

本阶段要求开发者暂时忘掉实现细节，按真实用户路径使用产品。重点不是找代码 bug，而是找：

- 不知道下一步做什么；
- 风险提示看不懂；
- 确认按钮缺少上下文；
- 失败后不知道如何恢复；
- 权限、审计和证据信息被埋在深层页面；
- 移动端关键操作不可用。

## 3. 第一轮：无脚本首次使用

测试者只能阅读 README，不得先看 API 文档。

### 任务 A：银行概览

- [ ] 能在 30 秒内找到账户、卡片、订阅；
- [ ] 能理解异常订阅提示；
- [ ] 能理解今日累计转账与风险阈值；
- [ ] 知道下一步可以去任务控制台。

### 任务 B：账单分析

- [ ] 能用自然语言发起账单分析；
- [ ] 能看出总支出、分类、异常交易；
- [ ] 能找到异常订阅 ID；
- [ ] 知道如何继续处理异常订阅。

### 任务 C：智能转账

- [ ] 能完成 880 元黄色确认；
- [ ] 能理解为什么是黄色；
- [ ] 同日再转 500 元时能理解为什么升级为红色；
- [ ] 能正确输入演示 OTP；
- [ ] 执行后能看到结果和审计入口。

### 任务 D：卡片管理

- [ ] 能找到额度、还款日、交易限额、挂失/解挂；
- [ ] 红色操作明确展示 MFA 要求；
- [ ] 操作后能在银行概览看到状态变化。

### 任务 E：权限与审计

- [ ] 能撤回某个工具权限；
- [ ] 撤权后再次操作能看到明确阻断原因；
- [ ] 能找到审计记录；
- [ ] 能理解哈希链校验状态；
- [ ] 能展开查看原始证据。

## 4. 第二轮：安全与异常路径

- [ ] 关闭后端后页面显示明确离线状态，不伪造成功；
- [ ] 提交重复请求不会创建重复任务；
- [ ] 确认后刷新页面不会重复执行；
- [ ] 错误 OTP 有明确提示；
- [ ] 拒绝确认后任务状态正确；
- [ ] 权限撤回期间待确认动作会复检并阻断；
- [ ] 空账户/空订阅/空账单有合理空状态；
- [ ] 不输入完整信息时能得到澄清提示；
- [ ] Prompt 注入请求不产生可执行任务。

## 5. 第三轮：修复后回归

- [ ] 三个场景连续完成；
- [ ] 确认、MFA、撤权、审计全部走通；
- [ ] 桌面截图和移动截图更新；
- [ ] README 截图与当前界面一致；
- [ ] 记录修复前后对比。

## 6. 问题记录模板

| 字段 | 内容 |
|---|---|
| 编号 | UX-001 |
| 场景 | 转账 |
| 严重度 | P0 阻断 / P1 严重 / P2 一般 / P3 建议 |
| 用户目标 | 用户想完成什么 |
| 实际发生 | 用户看到什么 |
| 预期行为 | 用户应该看到什么 |
| 影响 | 是否阻断、是否误解风险、是否无法恢复 |
| 证据 | 截图 / 复现步骤 |
| 修复建议 | 交互或文案层面建议 |
| 回归结果 | 通过 / 未通过 |

## 7. 退出标准

- 无 P0/P1 可用性阻塞；
- 三个核心场景从首次打开到完成均不超过 10 分钟；
- 风险等级、确认原因、执行结果、审计状态都能被非开发者理解；
- 桌面和移动端关键路径可用；
- 不再新增只有开发者知道的隐性操作。
