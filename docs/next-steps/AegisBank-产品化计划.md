# AegisBank 下一步开发计划：产品化

> 制定日期：2026-10-27
> 分析基线：`0xChainAegis/aegisbank@8273e5c`。
> 配套计划：[AegisBank 问题修复与升级计划](./AegisBank-问题修复与升级计划.md)
> 产品化含义：把当前可信银行原型升级为普通用户能理解、能连续使用、能回溯和控制的产品体验；不等同于真实银行生产上线。

## 1. 产品定位

### 1.1 一句话定位

**一个让用户看得懂、查得回、改得动，并且每次敏感执行都可核对的可信银行 AI 助手。**

### 1.2 目标用户任务

1. 用日常表达办理账单、转账、卡片、理财、订阅和跨场景任务。
2. 在执行前看懂“系统理解了什么、还缺什么、将发生什么”。
3. 在多轮对话中补充和修改未执行草稿，并确认旧授权不会被套用。
4. 查看历史办理过程与结果，而不是只看到最后一次运行。
5. 获得可解释的个性化建议，同时能查看、纠正和删除偏好。
6. 普通用户只接触业务语言；开发者和评委可按需查看 DAG、哈希、证据与审计。

### 1.3 非目标

- 不用聊天外观伪装已经具备任意上下文推理。
- 不把技术控制台全部删除；将其保留为独立的“安全与开发工作台”。
- 不增加真实银行、真实 MFA、真实 IM 或生产安全的虚假承诺。
- 不让推荐、历史记录或个性化卡片直接触发写操作。
- 不为了视觉效果新增后端没有事实依据的指标和图形。

## 2. 当前体验差距与产品策略

| 当前差距 | 产品策略 | 对应工作包 |
|---|---|---|
| 单任务输入与 `lastRun`，缺少连续对话 | 会话时间线 + 版本化草稿 + 可恢复状态 | P1 |
| NLP 来源和澄清对用户不够可见 | 理解摘要、参数来源、实体候选选择 | P1 |
| 技术术语和内部状态影响理解 | 业务语言首屏，技术证据分层展开 | P1 |
| 历史只能看运行/审计，不适合普通用户 | 用户操作记录与审计视图分离并关联 | P1 |
| 缺少个性化和用户控制 | 可解释建议卡 + 偏好管理中心 | P2 |
| 部署、重置和演示数据准备成本较高 | 已组装运行包、一键检查、固定演示种子 | P1 |
| 文档、截图、视频和数字存在版本漂移 | 单一发布清单与当前证据驱动交付 | P1 |

## 3. 信息架构与用户流程

### 3.1 建议主导航

1. **银行助手**：对话、理解、确认、回执和历史会话。
2. **我的账户**：账户、卡片、持仓、订阅及业务图表。
3. **操作记录**：普通用户可读的任务时间线，支持按会话查看。
4. **我的偏好**：常用对象、查询偏好、提醒偏好及隐私控制。
5. **安全与开发工作台**：权限、风险、DAG、ActionEnvelope、审计、渠道和运维，按需展开。

“操作记录”面向用户；“审计链”面向核查。两者可以关联，但不混成同一页面。

### 3.2 对话时间线的消息类型

| 类型 | 展示内容 | 禁止行为 |
|---|---|---|
| 用户消息 | 原始输入、发送时间 | 不把未提交草稿显示为已发送 |
| 理解摘要 | 意图、对象、金额、账期、来源和未覆盖片段 | 不把候选语义说成银行事实 |
| 澄清消息 | 缺失项、歧义候选、可选择的下一步 | 不用泛化错误让用户整句重说 |
| 草稿/计划 | 将执行的动作、顺序和版本 | 不显示成已完成 |
| 确认卡 | 对象、金额、账户/卡尾号、风险原因、真实倒计时 | 不使用固定错误或误导性文案 |
| 业务回执 | 服务端本次执行结果、业务编号、模拟标识 | 缺字段不猜，失败/未知不显示成功 |
| 系统状态 | 未就绪、过期、版本冲突、熔断和恢复入口 | 不把所有问题都写成“写操作被拒绝” |
| 证据入口 | 查看计划、风险、确认和审计 | 默认不干扰普通业务流程 |

## 4. P1：对话式银行助手 MVP

### 4.1 会话与时间线

- [ ] 用会话时间线替代单一 `lastRun` 作为主要产品形态，保留原单任务工作台作为开发/回退视图。
- [ ] 支持新建会话、恢复当前会话、查看本人历史会话和刷新后恢复。
- [ ] 每条用户输入、理解、确认和回执通过 `session_id / turn_id / run_id` 关联。
- [ ] 用户编辑下一条输入时，不改写上一条已经提交的消息或回执。
- [ ] 加载历史时保留服务端状态，不用本地缓存伪造待确认或已完成状态。
- [ ] 历史查询失败、为空、过期和跨用户拒绝均有明确界面状态。

### 4.2 有界多轮交互

首版只支持技术升级计划定义的三类能力：

1. 回溯：“我刚才要转给谁、多少钱”。
2. 补槽：“给妈妈转钱” → “五百”。
3. 修订：“不是 500，改成 300”。

交互要求：

- 当前正在补充或修订哪份草稿必须可见，可退出并改为新任务。
- 修订后显示版本变化及需要重新确认的原因。
- 旧确认卡标记失效，不能继续点击执行新计划。
- 已执行记录只提供“发起新操作”或可用的受控补偿入口，不提供“编辑历史”。
- 重复点击、网络重试和刷新不能生成重复消息对应的业务动作。

### 4.3 理解摘要与候选选择

- [ ] 展示“我理解为”摘要，列出对象、金额、日期和动作；关键参数可展开查看原文来源。
- [ ] 多卡、多联系人、多订阅时使用候选选择，不让用户手输内部 ID。
- [ ] 未知字段显示“未提供/未核验”，不得显示为 0、正常或安全。
- [ ] 将模型候选、确定性解析、Mock Bank 事实和执行结果分层标注。
- [ ] 对不支持的条件或组合说明“哪一部分暂不支持”，不能只返回通用失败。

### 4.4 确认与业务回执统一

- [ ] 确认内容完全来自当前服务端计划与受控事实，前端不自行拼接收款人姓名。
- [ ] 风险原因、到期时间和 MFA 状态使用实际字段；倒计时结束后立即禁用旧确认。
- [ ] 转账明确区分本人账户调拨与对外收款；卡片明确尾号和操作类型。
- [ ] 回执只在对应状态允许时显示成功；`FAILED / UNKNOWN / RECONCILED / ROLLED_BACK` 使用不同文案和下一步。
- [ ] 所有金融结果继续显示“模拟银行结果”，不制造真实资金到账印象。

## 5. P1：业务语言、状态与可访问性

### 5.1 分层展示技术信息

- 首屏使用“待确认、执行中、已完成、需要补充信息、结果待核对”等业务语言。
- `DAG / plan_hash / ActionEnvelope / run_id / legacy` 等放入技术详情。
- 不单纯隐藏错误的后端原因；先修服务端口径，再由前端映射。
- 中英状态统一翻译，未知枚举保留原值并标注未知，不默认映射为正常。

### 5.2 必备界面状态

每个核心页面和弹窗都检查：

- loading / empty / error / offline / not-ready；
- 重复提交、过期、版本冲突、撤权和熔断；
- 手机键盘、弹窗焦点、返回焦点和屏幕阅读器标签；
- 390px 手机宽度无整页横向溢出；
- 长姓名、长错误原因、大金额和空数据不会破坏布局。

## 6. P2：可解释个性化与偏好中心

### 6.1 建议卡

建议只以卡片或候选形式出现，例如：

> 推荐联系人：妈妈
> 原因：近 3 个月你曾向该联系人转账 4 次
> 操作：选择 / 换一位 / 不再推荐

约束：

- 点击建议只填入或生成新草稿，不直接执行。
- 金额、对象、风险和确认仍以当前请求重新核验。
- 不展示“系统已了解你，所以无需确认”等误导话术。
- 冷启动时使用普通默认界面，不生成虚假个性化解释。

### 6.2 我的偏好

- [ ] 查看偏好来源、最近更新时间和使用范围。
- [ ] 修改、删除、单条停用和全部重置。
- [ ] 删除后界面和建议结果同步失效，刷新后不得恢复。
- [ ] 提供简明的数据说明：保存什么、用于什么、保存多久。
- [ ] 偏好写入失败、版本冲突和跨用户拒绝有可理解反馈。

## 7. P2：六场景产品化表达

不新增无后端支撑的业务，优先改善现有六场景的可理解性：

| 场景 | 产品化重点 |
|---|---|
| 转账 | 联系人候选、确认对象、累计风险原因、定时任务状态和恢复入口 |
| 账单 | 分类图表、消费与内部调拨口径说明、异常证据和原始流水联动 |
| 理财 | 模拟产品/收益标识、风险适当性、持仓与订单状态，不承诺收益 |
| 卡片 | 卡尾号选择、冻结与挂失区别、操作前后状态和 MFA |
| 订阅 | 涨价证据、续费提醒、取消对象和生效状态 |
| 跨场景 | 用用户目标展示步骤和依赖，技术 DAG 作为可展开视图 |

图表只使用当前服务端事实；没有数据时显示空状态，不填充编造示例。

## 8. P1：可安装、可重置、可演示

### 8.1 降低运行门槛

- [ ] 提供已组装的演示运行包，避免使用者手工理解六职责包结构。
- [ ] 保留 Linux/WSL 边界；只有实际验证后才宣称原生 Windows 或 Docker 支持。
- [ ] 一键完成依赖检查、组装、启动、readiness 检查和浏览器入口提示。
- [ ] 提供独立演示数据库、固定种子和安全重置脚本；重置不得碰开发数据库。
- [ ] 默认离线 Planner 可运行；模型未配置时明确显示当前模式。
- [ ] 启动后自动检查前端、后端、数据库和审计链，不让用户到操作中段才发现未就绪。

### 8.2 演示可靠性

- 固定“一个用户的一天”演示数据和操作顺序。
- 对会改变余额、累计风险、订阅和卡片状态的步骤提供一键重置。
- 演示前检查 OTP、MFA、确认恢复、审计验证和手机宽度。
- 真实模型演示准备离线降级方案，但不得把降级结果冒充真实模型成绩。

## 9. 与技术升级线的接口

| 产品能力 | 后端契约来源 | 前端职责 |
|---|---|---|
| 会话与历史 | conversations / turns / timeline | 展示、导航、恢复，不推断权限 |
| 补槽与修订 | drafts / amend / version / plan_hash | 显示版本变化，作废旧确认卡 |
| 理解摘要 | SemanticAnalysis / SemanticFrame / evidence | 展示来源和候选，不伪造银行事实 |
| 个性化 | suggestions / preferences | 选择、解释、删除和重置，不直接写业务 |
| 确认与回执 | 当前计划、确认状态、执行结果 | 只展示服务端事实和状态 |
| 审计入口 | audit / evidence / journal | 按需展开，不替代用户操作记录 |

协作规则：

1. 后端先给请求/响应样例、错误码和 Mock fixture，再并行开发。
2. 前端不内嵌业务权限判断，不使用 `X-Aegis-Role` 以外的自创角色逻辑。
3. 服务未就绪时所有写控件 fail closed。
4. 不用前端状态修补后端错误，不在 UI 中暗改金额、对象或执行结果。
5. Mock 联调通过后必须再做一次真实服务端联调。

## 10. 分阶段交付

### M0：可演示基线

- 合入并验收 P0 修复。
- 统一账单口径、确认文案和状态显示。
- 准备独立演示库、启动检查和发布清单。

### M1：对话 MVP

- 会话时间线、历史恢复、理解摘要和候选选择上线。
- 打通一次补槽、一次修订和一次事实回溯。
- 验证旧确认失效、刷新恢复、幂等和跨用户隔离。

### M2：个性化与六场景体验

- 上线可解释建议卡和“我的偏好”。
- 完成账单图表、卡片/订阅状态、跨场景用户目标视图。
- 完成手机、异常状态和可访问性检查。

### M3：参赛发布包

- 已组装运行包、固定演示数据、当前截图和真实复现步骤。
- 更新 README、ROADMAP、SECURITY、技术文档、安全自评和测试复现。
- 完成视频、答辩脚本和现场降级预案。

## 11. 用户验收与产品指标

### 11.1 必过任务

- [ ] 新用户不看 API 文档，可完成账单查询、转账确认和卡片挂失。
- [ ] 用户能完成“给妈妈转钱 → 五百 → 改成三百 → 重新确认”，并说出每一步为什么发生。
- [ ] 用户能查询“我刚才要转给谁、多少钱”，答案与历史一致。
- [ ] 旧确认、重复提交、刷新、过期和版本冲突不会误执行。
- [ ] 用户能删除一个偏好，且后续建议不再使用它。
- [ ] 用户 A 看不到用户 B 的历史、草稿、偏好或回执。
- [ ] 390px 手机和桌面均能完成核心流程。
- [ ] not-ready、离线、失败和 UNKNOWN 均不会显示成功。

### 11.2 建议度量

- 核心任务完成率、平均完成步数和需要开发者协助的次数。
- 澄清后继续完成率、非必要澄清率和草稿修订成功率。
- 确认前发现对象/金额问题的比例，而不是只追求确认点击率。
- 建议采纳率、错误建议反馈和偏好删除后的失效正确率。
- 首次启动成功率、演示重置成功率和真实联调通过率。

指标必须先定义分母和测量方法；没有实测前不写具体提升百分比。

## 12. 五分钟演示建议

1. **账单与理解**：用一句口语查询账单，展示理解摘要和真实分类结果。
2. **多轮转账**：发起“给妈妈转钱”，补充“五百”，再修订为“三百”。
3. **安全确认**：展示新计划、对象、金额、风险与 MFA；旧确认已失效。
4. **回执与回溯**：完成 Mock 执行，追问“我刚才转了多少”，历史回答与回执一致。
5. **个性化控制**：展示常用联系人建议及原因，删除偏好后建议消失。
6. **信任证据**：最后展示计划哈希、幂等重放和审计链验证，明确模拟与生产边界。

如果某项尚未通过真实联调，就从正式视频脚本移除，不以设计稿或 Mock 前端冒充完成能力。

## 13. 发布完成定义（Definition of Done）

- [ ] 核心流程由非实现者按用户任务独立验收。
- [ ] 前端测试、真实服务端联调、生产构建和安全回归通过。
- [ ] 页面、截图、视频和文档来自同一版本与同一功能状态。
- [ ] 所有数字由当前测试或评测输出产生，历史数字注明基线。
- [ ] 没有“通用 NLP、生产安全、真实银行、真实 MFA、真实 IM”等超出证据的宣传。
- [ ] 演示数据可重置，离线降级可复现，现场失败有明确处理脚本。
- [ ] 产品界面继续体现：习惯可以学习，授权不能继承；历史可以回溯，确认不能重放。
