## 开发启动：仓库根目录执行

后端使用 Linux / WSL。需要 Python 3.11+、`uv`、`pnpm`，Node.js 满足 `^22.22.2 || ^24.15.0 || >=26.0.0`。

```bash
python3 scripts/assemble.py
bash scripts/bootstrap.sh

# 必须选择尚不存在的新文件；$PWD 将路径展开为仓库内的绝对路径。
DEMO_DB="$PWD/.runtime/backend/data/mia-day1-20261026-01.db"
test ! -e "$DEMO_DB" && \
  AEGIS_DATABASE_PATH="$DEMO_DB" bash scripts/dev.sh
```

首次使用不存在的库文件，后端会自动建库并写入基础模拟种子，无需手工迁移。若同名文件已经存在，上面的检查会阻止启动；把编号换成 `02` 等新的文件名再运行。需要另一轮干净状态时，先在本轮启动终端按 `Ctrl+C` 停止前后端，再换新的库文件启动。保留任何已有数据库。

- 页面：`http://127.0.0.1:5173`
- 后端：`http://127.0.0.1:8000`
- 就绪检查：`http://127.0.0.1:8000/api/health/ready`
- 接口说明：[API-HANDOFF.md](API-HANDOFF.md)

前端开发服务器将 `/api` 代理到本机8000端口。这些地址用于开发者同机浏览器；共享屏幕时由开发者电脑运行。

## 三张固定任务卡

开发先确认：使用本轮新库；页面为 `USER` 角色；系统为 `ready`；相关工具已授权；今日转账累计为0；`CARD-8821` 为初始正常状态。建议为本轮打开独立的无痕浏览器窗口，避免旧库的本地待确认快照混入。

所有账户、交易和验证码均为模拟。界面不就绪、对象或金额与任务不符时，停止操作并记录页面，由开发处理。

### 任务一：查看账单

- 输入：`分析我的本月账单`
- 预期：绿色只读查询完成，展示账单结果，无需人工确认。
- 观察：能否找到结果，能否判断这是查询、没有发起资金操作。
- 停止规则：看到结果后结束本任务，不继续取消订阅或发起其他操作。

### 任务二：核对小额转账计划

- 输入：`向 ACC-2002 转账 880 元`
- 预期：在上述新库条件下为黄色待确认，展示收款账户、880元金额和风险原因；此时尚未转账。
- 观察：用户能否准确说出收款方、金额，以及当前是否已经执行。
- 停止规则：核对后选择“拒绝执行”，结束待确认操作，保持本轮累计转账为0。

### 任务三：识别强验证与失败提示

- 输入：`挂失我的卡片 CARD-8821`
- 预期：红色待确认，要求演示MFA；确认前卡片尚未挂失。
- 演示验证：选择OTP，仅试一次错误验证码 `000000`。预期提示验证未通过，操作不执行，仍可处理这笔待确认任务。
- 观察：用户能否分清“等待验证”“验证失败”和“操作完成”。
- 停止规则：错误验证码后选择“拒绝执行”；不输入正确令牌完成挂失。出现未知状态或无法继续时，停止并保留输入、截图和任务标识。

观察时先让用户独立操作和复述，再提供帮助。记录匿名原话、卡点及提示发生的位置；提示后的回答单独标明，不作为独立理解的证据。数据库是否发生写入等技术结论由启卓核对。
