The Gap

Agent 能调用工具，不等于银行敢让它执行。

当自然语言进入真实金融场景，真正的难题不是生成一句回答，而是让每一次工具调用都可知、可控、可拒绝、可追溯。

意图不可控

模型直接选择函数、拼接参数，缺少确定性 Schema 与 DAG 校验，错误调用难以及时发现。

风险一刀切

只看工具名称，无法结合金额、当日累计与账户状态动态升降级，体验与安全难以平衡。

权限不可见

用户不知道 Agent 被授予了什么能力，也无法在操作前撤回某个工具的访问权。

过程不可证

谁在何时基于哪份计划、什么风险原因执行了什么操作，事后缺少可校验的证据链。

AegisBank 的答案：把 Agent 放进控制平面

Planner 只产出计划，Compiler 先校验，风险引擎给出理由，权限网关统一裁决，确认状态机承接人机边界，审计链同步留痕。

Plan 不直接执行工具 风险只升不降 权限逐工具授权 DAG 变量受控解析 确认后再次复检 哈希链可验证
Three Scenarios

三个高频银行场景，一条统一的治理链路。

从转账到账单洞察再到卡片安全操作，每个入口都经过同一套 Planner、Compiler、动态风险、权限网关与审计管线。

01 · TRANSFER动态风险

智能转账

根据金额与当日累计自动升级风险；黄色确认，红色强验证，执行后更新模拟余额与流水。

向 ACC-2002 转账 880 元
1 解析账户、金额与计划哈希 2 动态风险：880 元 → 黄色确认 3 同日再转 500 元 → 累计 1380 元 → 红色 4 确认 / 演示 OTP 后模拟执行
02 · BILL自动执行

账单分析

读取 Mock Bank Core 的账单与订阅事实，给出支出分类、近期交易和异常订阅提示。

分析我的本月账单
1 只读查询，绿色直接执行 2 聚合本月消费分类 3 识别可疑订阅 SUB-3002 4 返回可疑订阅 ID 与原因

卡片管理

调整还款日、额度与交易限额，或执行挂失与解挂；敏感设置变更必须经过分级确认。

Dynamic Risk

风险不是提示词里的一句话。

工具 Manifest 给出基线风险，动态风险引擎基于确定性事实只保持或上调等级。LLM 不参与风险判断，确认执行前还会重新评估。

每次操作都会得到可解释的风险评分与原因，并同时出现在计划步骤、Agent 响应、确认动作和审计记录中。

风险输出：level · score · reasons · base_risk · requires_reauth。任一 DAG 节点被拒绝，整个任务阻断；任一步骤需确认，整个 DAG 先暂停。

Trust Boundary

清晰展示能力，也清晰标注边界。

AegisBank 是安全自治 Agent 的可运行原型，而不是生产银行系统。可信来自可验证的控制点，而不是夸张的安全承诺。

原型中已落地

  • Mock Bank Core：账户、卡片、交易、订阅与账单事实由 SQLite 仓库提供
  • 9 个工具 Manifest：最小权限、输入 Schema 与基线风险声明
  • 确定性 Plan Compiler：工具注册、参数校验、DAG 环检测与 plan_hash
  • 动态风险引擎：金额、当日累计与操作类型触发绿/黄/红等级与原因
  • 统一权限网关：逐工具授权、Prompt 注入拦截、拒绝即阻断
  • 跨场景 DAG：前序结果变量解析，账单分析后取消异常订阅
  • 确认状态机：TTL、拒绝、过期、确认后权限与风险复检
  • SHA-256 审计哈希链与完整性校验 API

不声称具备

  • 不连接真实银行核心、支付网络或客户数据，不产生真实资金变动
  • 不提供生产级登录、设备指纹、真实短信/人脸/U 盾 MFA
  • 动态风险不是生产反欺诈或信用决策模型
  • SQLite 不满足银行级高可用、隔离、容灾与 WORM 审计要求
  • 尚无步骤级回滚、补偿交易、异常熔断与工具执行沙箱
  • 注入检测、限流、CSRF/mTLS 与渗透测试仍需生产化补齐
