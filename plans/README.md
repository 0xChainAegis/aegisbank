## 从「找功能」到「说需求」

手机银行的功能越来越多，入口却越来越深。AegisBank 希望让用户只用一句话表达需求，就能完成查询、转账、账单分析、理财与卡片管理等操作。

但银行场景不能只追求“能做”，还必须回答：**谁可以做、做到哪一步、如何确认、出错怎么办。**

因此，AegisBank 不让大模型直接调用银行工具，而是在用户意图与业务执行之间加入一层可信控制平面：**先规划、再分级、后执行，全程留痕。**

> 例如：“分析我的账单，并取消异常订阅。”
>
> Agent 会先拆解为账单分析与订阅取消两个步骤。查询自动执行；涉及状态变更的取消操作则展示详情，等待用户确认。

## 核心能力

### 一句话，覆盖六类银行场景

- **智能转账**：按联系人、别名或手机号转账，支持 AA 拆分、定时与周期转账。
- **账单分析**：生成月度 / 年度账单，识别异常交易、重复扣费与订阅金额突增。
- **理财操作**：风险测评、模拟持仓与收益查询，以及申购、赎回流程。
- **卡片管理**：额度与交易限额调整、还款日修改、挂失解挂、虚拟卡申请。
- **订阅 / 代扣**：发现订阅扣费、提供续费提醒，并支持确认后取消订阅。
- **跨场景联动**：从账单分析联动取消异常订阅，或把生日准备拆成“查日期 → 锁预算 → 订鲜花与蛋糕”的多步任务。

试着对它说：

```text
向 ACC-2002 转账 880 元
分析我的本月账单
和妈妈、老爸、张三 AA 300 元（4 人）
帮我准备下个月妈妈的生日，预算 1000 元
```

六场景均有可运行链路，但不代表每个银行子业务、自然语言表达或生产流程都已完整覆盖。

金额支持“五百块”“1,500 元”等明确表达；遇到歧义金额、尚不支持的条件或组合指令，系统会要求澄清，不会把已识别的组合请求简化为其中一步。通用指代、对话纠错与自由组合规划仍待完善，见 [NLP 现状与 P0 修复](docs/NLP-ASSESSMENT-AND-PLAN-2026-10-25.md)。

## 产品体验

### 用户看到的不只是答案，还有接下来要发生的事

AegisBank 把执行计划、步骤依赖、风险等级与确认状态放到同一个任务控制台中。复杂任务会拆解为有序 DAG；涉及前序结果时，后续步骤可以引用上游数据，而不是让模型猜测。

**绿色操作直接办，黄色操作先确认，红色操作再强验证。**

- 🟢 **绿色｜自动执行**：余额、账单、持仓等只读查询。
- 🟡 **黄色｜用户确认**：小额转账、取消订阅、调整部分账户设置。
- 🔴 **红色｜确认 + 二次验证**：大额或累计风险升级的转账、理财申购、卡片挂失等。

风险会根据金额、当日累计和操作类型动态调整，且**只能保持或上调，模型不能降低风险等级**。例如，单日累计规则下，一笔 880 元转账可以是黄色；同日再转 500 元，累计超过 1000 元后会升级为红色。

## 安全设计

### 真正能“办事”的 Agent，也必须会“踩刹车”

AegisBank 把安全机制嵌入每一笔操作，而不是附加在回答之后：

1. **计划与执行分离**：Planner 只生成候选计划；Compiler 校验工具、参数、依赖和 DAG，模型无权直接执行。
2. **统一权限入口**：所有工具调用都经过同一网关，依次检查注入风险、角色能力、工具授权与分级决策。
3. **确认内容不可调包**：待确认动作绑定计划哈希、参数哈希、风险、权限、一次性 nonce 与有效期；执行前再次复核。
4. **重复提交不重复执行**：幂等键与一次性确认机制避免重复创建动作或重复扣款。
5. **异常不会被包装成成功**：支持失败关闭、可疑行为熔断、步骤暂停 / 恢复、补偿回退，以及 `UNKNOWN` 人工对账。
6. **每次决定都有证据**：原始指令、DAG、工具入参、执行结果与确认状态写入 SHA-256 审计哈希链，可在线校验。

## 技术底座

```text
自然语言
   ↓
Planner → Plan Compiler → 动态风险引擎 → 统一权限网关
   ↓
分级确认 / 演示 MFA → ToolExecutor + 执行守卫 → Mock Bank Core
   ↓
证据分层 + SHA-256 审计链
```

- **前端**：React 19、TypeScript、Vite，提供银行概览、任务、权限、运维与审计控制台。
- **后端**：Python 3.11+、FastAPI、Pydantic、SQLite。
- **AI 规划**：默认规则 Planner 可完全离线运行；可选 OpenAI-compatible LLM，并支持自动回退。
- **扩展方式**：业务场景与横切安全能力采用模块化自动发现，渠道适配器复用同一安全执行链。

深入阅读：[系统架构](docs/ARCHITECTURE.md) · [银行业务与六场景闭环](docs/BANKING-DOMAIN.md) · [安全设计](docs/SECURITY.md)

## 快速开始

### 环境要求

Linux / WSL Ubuntu 24.04，Python 3.11+、`uv`、Node.js 22.22.2+ 与 `pnpm`。

```bash
git clone https://github.com/LQZ5885/aegisbank.git
cd aegisbank

# 安装依赖
bash scripts/bootstrap.sh

# 同时启动前端与后端
bash scripts/dev.sh
```

启动后访问：

- 产品控制台：<http://127.0.0.1:5173>
- API 文档：<http://127.0.0.1:8000/docs>
- 就绪检查：<http://127.0.0.1:8000/api/health/ready>

红色操作的本地演示 OTP 为 `246810`。完整环境配置、演示数据与排障说明见[部署文档](deliverables/06-部署说明.md)。

### 推荐体验路径

1. 在银行概览查看账户、卡片、订阅与异常提示。
2. 执行“分析我的本月账单”，观察绿色查询与账单分析结果。
3. 执行“向 ACC-2002 转账 880 元”，完成黄色确认；同日再转 500 元，观察风险升级。
4. 执行“分析我的账单并取消异常订阅”，查看跨步骤 DAG 与确认流程。
5. 打开操作审计，校验哈希链；再体验撤权、熔断、补偿回退和人工对账。
