## 0. 视频规格

| 项 | 要求 |
|---|---|
| 分辨率 | 1920×1080（16:9），原生录制，不在剪辑里放大 |
| 帧率 | 30 fps（屏幕录制足够；动作快时可 60 fps） |
| 容器 / 编码 | MP4（H.264 + AAC） |
| 时长 | ≤ 5:00；本脚本按 5:00 编排，留 0–2 秒余量 |
| 画面 | 只录浏览器窗口与必要终端；不录桌面隐私、通知、聊天软件 |
| 音频 | 麦克风 48 kHz；建议单独录一条干净口播，后期对齐 |
| 录制工具 A（推荐） | OBS Studio：显示器采集 1920×1080 + 麦克风，CQP 18–20，MP4 |
| 录制工具 B | Microsoft Edge + Windows 系统录音（Xbox Game Bar 或系统录音机），录活动窗口 |
| 字幕 | 外挂 SRT；样式见 §5；不烧录进画面（便于修改） |
| 交付 | `aegisbank-demo-5min.mp4` + `aegisbank-demo.srt` + 封面/结尾板 PNG |

> 事实口径：演示数据全部来自 Mock Bank Core，不连接真实银行；OTP `246810`、模拟生物识别 `FACE-888888` 仅用于本地演示；理财内容不构成投资建议。

## 1. 录制前准备清单

### 1.1 环境与数据（必须先做）

1. 确认在 WSL2 Ubuntu 24.04 的真源仓库操作：
   ```bash
   cd /home/lqz5885/aegisbank/dev/aegisbank
   git rev-parse --short HEAD        # 期望 75df12b
   ```
2. **先停掉正在运行的后端**（SQLite 文件需要释放），再重置演示数据：
   ```bash
   bash scripts/seed-demo.sh
   ```
   期望输出包含：虚拟卡账户 `ACC-3003`、卡 `CARD-9001`、余额 `3000.00`、开卡流水 `TX-VCARD-001`。
3. 启动后端时**必须指向同一个库**（`scripts/dev.sh` 默认库不是 `dogfood.db`）：
   ```bash
   cd backend
   AEGIS_DATABASE_PATH="$PWD/data/dogfood.db" \
     uv run uvicorn aegisbank_api.main:app --host 0.0.0.0 --port 8000
   ```
4. 另开终端启动前端：
   ```bash
   cd frontend
   pnpm dev
   ```
5. 验证就绪与审计链：
   ```bash
   curl -s http://127.0.0.1:8000/api/health/ready
   curl -s http://127.0.0.1:8000/api/audit/verify
   ```
   期望：`status = ready`，`sqlite / audit_chain / mock_bank_seed / planner` 四个组件 `ok = true`；审计链 `valid = true`。
6. 打开 <http://127.0.0.1:5173>，确认顶部就绪横幅四个 chip 均为 **OK**，写操作按钮可用。

> 如果就绪横幅不是 `ready`：不要录写操作。先重启后端，再看 `/api/health/ready` 的具体组件；必要时重新执行 §1.1 第 2 步（停后端 → seed → 启动）。

### 1.2 浏览器窗口、标签页与缩放

- 使用 Edge 或 Chrome，窗口最大化到 1920×1080；浏览器缩放 **100%** 起步。若录制后字偏小，可调到 **110%**，最多不超过 **125%**（再大表格会换行、按钮会挤）。
- 隐藏书签栏（`Ctrl+Shift+B`）、关闭开发者工具、关闭侧边栏与扩展弹窗；只保留一个 AegisBank 窗口。
- 建议标签页：
  1. `http://127.0.0.1:5173`（主操作，用左侧导航 01–07 切换）；
  2. `http://127.0.0.1:8000/api/health/ready`（可选，用于拍就绪证据）；
  3. `http://127.0.0.1:8000/docs`（可选，不拍进成片）。
- 页面导航固定用左侧 `01 银行概览 / 02 六场景面板 / 03 任务控制台 / 04 权限控制台 / 05 2A 能力 / 06 运维面板 / 07 操作审计`，不要用浏览器前进/后退，避免状态错位。
- 关闭无关通知：Windows 专注助手 / 勿扰模式、Edge 通知、微信 / 钉钉 / Slack / 邮件；任务栏设为自动隐藏；关闭录屏软件自身悬浮窗。
- 鼠标指针保持可见，移动慢；不要停在余额、卡号、终端路径等隐私文本上。

### 1.3 三个终端窗口（建议）

| 终端 | 用途 | 预先准备的命令 |
|---|---|---|
| T1 | 后端日志 | `AEGIS_DATABASE_PATH="$PWD/data/dogfood.db" uv run uvicorn aegisbank_api.main:app --host 0.0.0.0 --port 8000`（在 `backend/`） |
| T2 | 前端日志 | `pnpm dev`（在 `frontend/`） |
| T3 | 演示用 API | `curl -s http://127.0.0.1:8000/api/health/ready`；`curl -s http://127.0.0.1:8000/api/audit/verify`；镜头 8 的时间快进命令（见下） |

- 终端提示符改成不含用户名/主机名的形式，例如 `export PS1='$ '`，并 `clear`。
- 终端字号 16–18 pt；只保留 T3 入镜，T1/T2 可最小化（保留日志用于排查）。
- 镜头 8 的时间快进命令（复制到 T3，先不回车）：
  ```bash
  NOW=$(date -u -d '+400 days' +%Y-%m-%dT%H:%M:%SZ)
  curl -s -X POST -G 'http://127.0.0.1:8000/api/automation/run-due' \
    --data-urlencode "now=$NOW"
  ```
  > UI 的「时间快进」按钮只执行**当前已到期**任务；生日礼物在生日前 2 天才到期，所以镜头 8 用带 `now` 参数的 API 快进到到期之后。这是演示接口，不是真实 cron。

### 1.4 录制与音频

- OBS：新建「显示器采集」1920×1080，输出 30 fps、MP4、CQP 18–20；音频采样 48 kHz；先录 10 秒试看，确认没有黑边、缩放和爆音。
- 麦克风离嘴 10–15 cm，录 5 秒环境音；正式开录前打一次板（或拍手），方便后期对齐。
- 先完整彩排 1–2 遍并计时；每个镜头超时超过 3 秒就压缩台词，不要加速画面。
- 正式录制前再执行一次「停后端 → `bash scripts/seed-demo.sh` → 启动后端」，确保余额、累计转账、订阅状态、审计条数都是干净基线。

### 1.5 隐私与合规

- 不出现 `.env`、API Key、真实姓名、手机号、真实卡号、聊天记录、公司内网地址。
- 终端路径中的用户名可用提示符替换或后期遮挡；浏览器使用干净配置文件，避免历史记录/书签入镜。
- 只使用 `demo-user` 与模拟数据；不要登录任何真实银行/支付/IM 账号。

每条操作都进入 07 操作审计。顶部显示哈希链完整和已校验记录数；展开任意一条，可以看到原始指令、DAG 路径、工具入参、确认状态，以及 Mock 数据、人工确认、策略判断、审计哈希链四层证据。任何一条被改动，校验都会失败。

**镜头 10 · 3:26–3:36（约 10 秒）**
切换角色：OPERATOR 只能做运维，不能发起银行操作；AUDITOR 只读审计，不能改权限。

**镜头 11 · 3:36–3:46（约 10 秒）**
运维面板展示熔断状态、三类触发规则和最近事件；熔断打开时，写操作会 fail closed。

**镜头 12 · 3:46–3:56（约 10 秒）**
沙箱演示：网络访问被拦截，拦截事件写入审计，而不是悄悄失败。

**镜头 13 · 3:56–4:06（约 10 秒）**
同一条链路也接受 IM 消息；message_id 保证重复投递不会二次执行。

**镜头 14 · 4:06–4:24（约 18 秒）**
MFA、沙箱、IM、回退补偿、熔断和多角色，全部复用同一套 Planner、权限网关、执行器和审计链。

**镜头 15 · 4:24–5:00（约 36 秒）**
AegisBank 想证明的不是模型会聊天，而是银行 Agent 可以被治理：意图可解释、风险可分级、权限可撤回、执行可补偿、结果可审计。所有账户与交易均为模拟数据，不连接真实银行；演示 OTP 与生物识别只用于本地。代码、测试和复现步骤已随作品提交。

> 语速提示：上述约 790 字对应 5:00 约 160 字/分钟。若现场口播偏快，可在镜头之间留 0.5 秒；若偏慢，优先压缩镜头 1/2/7 的第二句，不要压缩镜头 5/8/9 的结论。

## 5. 字幕文件建议（SRT）

### 5.1 分段规则

1. **一条字幕 = 一个语义短句**；最多 2 行，每行 14–18 个汉字，单条不超过 36 个汉字。
2. 每条持续 **2–5 秒**，最短不低于 1.5 秒；镜头切换处不跨条；不要一条字幕横跨两个操作。
3. 数字、英文、专有名词保留原样：`ACC-3003`、`CARD-9001`、`ActionEnvelope`、`OTP`、`DAG`、`SHA-256`；中英文之间留一个空格。
4. 时间码格式 `HH:MM:SS,mmm`，箭头前后各一个空格；序号从 1 递增；文件 UTF-8 无 BOM、LF。
5. 字幕放在画面底部安全区（下边距 ≥ 8%），不要遮挡确认按钮、风险徽标、审计哈希。
6. 与口播同步：字幕可比声音早 0.2–0.3 秒出现；长句拆成两条，不要靠加快语速硬塞。

### 5.2 示例（前 4 条，可直接扩展）

```srt
1
00:00:00,000 --> 00:00:03,200
AegisBank · 可信银行 AI 智能体

2
00:00:03,200 --> 00:00:07,000
四项就绪检查全部通过

3
00:00:07,000 --> 00:00:11,500
虚拟卡账户 ACC-3003：3000 元

4
00:00:11,500 --> 00:00:15,000
卡片尾号 9001 · 数据均为模拟
```

**封面板（0:00 前 1.5 秒，或作为视频封面图）**

## 6. 常见录制问题与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| 字太小 / 画面糊 | 1080p 下缩放 100% 仍偏小；剪辑放大 | 浏览器调到 110%（最多 125%）；OBS 原生 1920×1080；不要在剪辑里放大超过 100%。 |
| 录到隐私 | 书签、历史、通知、终端用户名、路径 | 干净浏览器配置；`export PS1='$ '`；专注助手；后期遮挡用户名/主机名；不出现 `.env`。 |
| `seed-demo.sh` 后仍不是 3000 元 | 后端指向了默认库，不是 `dogfood.db` | 停后端；确认 `AEGIS_DATABASE_PATH="$PWD/data/dogfood.db"`；重跑 seed；刷新页面。 |
| 命令报错 / 找不到 `uv` | 不在 WSL、PATH 不含 `~/.local/bin`、cwd 不对 | 用 `wsl -d Ubuntu-24.04` 进入；`cd` 到仓库；`bash scripts/bootstrap.sh`；`command -v uv`。 |
| 8000 / 5173 端口被占 | 旧进程未退出 | `ss -ltnp \| grep -E '8000\|5173'`；结束旧进程；或改用其他端口并同步前端代理。 |
| 就绪横幅非 `ready` | 后端未起、SQLite 不可用、审计链异常、种子缺失 | 看 `/api/health/ready` 的四个组件；重启后端；必要时停后端 → seed → 启动。 |
| 红色确认输错 OTP | 输错 `246810`、确认过期（默认 300 秒） | 重新发起任务，重新确认；不要复用已过期的弹窗。 |
| 撤权后忘记恢复 | 镜头 6 只撤未授 | 回 04 点「授予」；否则后续转账/生日任务会被阻断。 |
| 时间快进执行 0 条 | 生日礼物尚未到期；UI 按钮不带 `now` | 用 §1.3 的 `run-due?now=...+400 days`；或检查 02 页 `run_at`。 |
| 审计链异常 | 手工改库、旧库残留、并发写 | 停后端 → `bash scripts/seed-demo.sh` → 启动；重录镜头 9。 |
| 画面有黑边 / 比例不对 | 采集源不是 16:9 或缩放 | OBS 采集 1920×1080，缩放「适应屏幕」；输出 1920×1080。 |
| 音画不同步 | 音频单独录、未对齐 | 开录拍手；剪辑里以拍手帧对齐；统一 48 kHz。 |
| 录到通知/弹窗 | 系统/IM 通知 | 勿扰模式；关闭微信/钉钉/Slack/邮件；关 OBS 悬浮窗。 |

### 6.1 失败重录节点

| 失败镜头 | 是否要重置数据 | 建议 |
|---|---|---|
| 镜头 1/2/3 | 否 | 直接重录；镜头 3 会取消 `SUB-3002`，若已取消，重录镜头 3 前先 seed。 |
| 镜头 4/5（转账余额/累计已变） | 是 | 停后端 → seed → 启动，从镜头 1 或镜头 4 前重录；镜头 5 的 OTP 失败可只重录确认段。 |
| 镜头 6（撤权未恢复） | 否 | 04 恢复 `transfer` 授权，重录镜头 6；不需要重置。 |
| 镜头 7（理财订单已创建） | 建议 | 订单会叠加；重置后从镜头 7 前重录，或接受多笔模拟订单但口播不要报具体持仓数。 |
| 镜头 8（生日订单已创建/已执行） | 是 | 重置后从镜头 7 或 8 前重录；重复执行会叠加预算/订单。 |
| 镜头 9 | 否 | 只重录 07；审计是只追加的，旧记录仍在。 |
| 镜头 10–14 | 否 | 可重复录制；沙箱/IM 会产生新审计事件，不影响结论。 |
