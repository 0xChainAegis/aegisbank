## 0. 适用范围

本文说明如何在**本地开发/演示环境**启动 AegisBank，包括环境要求、一键启动、演示数据、验证命令、配置项、端口与代理、常见问题、生产化差距和交付前检查清单。

本文不覆盖真实银行生产部署。所有金融数据均为 Mock Bank Core 模拟数据，不连接真实银行系统，不产生真实资金变动；演示 OTP `246810` 与模拟生物识别 token `FACE-888888` 仅用于本地演示。生产化要求见 §8 与 [`05-安全自评报告.md`](05-安全自评报告.md) §4。

## 1. 环境要求

### 1.1 支持矩阵

| 项 | 推荐 / 要求 | 说明 |
|---|---|---|
| 操作系统 | **Windows 11 + WSL2 Ubuntu 24.04**（推荐）或 **Linux（Ubuntu 24.04）直接运行** | 项目主线在 WSL2 ext4；不建议在原生 Windows 或 `/mnt/d` 上运行 |
| Python | **3.12**（项目要求 `>=3.11`） | 后端 FastAPI / Pydantic；使用 `uv` 管理 |
| Python 包管理器 | `uv` | `backend/uv.lock` 锁定依赖；`bash scripts/bootstrap.sh` 执行 `uv sync --frozen` |
| Node.js | **22 LTS**（README 允许 20.19+ / 22.12+） | 前端 React 19 + Vite 7 |
| Node 包管理器 | `pnpm` | `frontend/pnpm-lock.yaml` 锁定依赖；`pnpm install --frozen-lockfile` |
| 浏览器 | 现代 Chrome / Edge / Firefox | 需要 JavaScript；界面为 React 控制台 |
| 端口 | `5173`（UI）、`8000`（API） | 均只在本机使用；无需对外暴露 |
| 外部服务 | 默认无 | `rule` Planner 完全离线；LLM 为可选依赖 |
| 硬件 | 普通开发机 | 无 GPU 要求；本地 SQLite 即可 |

### 1.3 目录位置

推荐路径：

```text
/home/lqz5885/aegisbank/dev/aegisbank     # WSL2 ext4，唯一开发主线
```

Windows 侧只用于展示/备份，不建议在 `D:\开发交流\mia03-ether\aegisbank智能体` 或 `/mnt/d/...` 上直接运行：`/mnt` 的 I/O、换行符与权限行为会和 Linux 原生环境不同，容易出现脚本不可执行、SQLite 锁异常、文件监听失效等问题。


脚本做两件事：

1. `cd backend && uv sync --frozen`：按 `uv.lock` 安装后端依赖；

## 2. 一键启动

### 2.1 同时启动前后端（推荐）

```bash
cd /home/lqz5885/aegisbank/dev/aegisbank
bash scripts/dev.sh
```

`scripts/dev.sh` 会：

- 在 `backend/` 启动 `uv run uvicorn aegisbank_api.main:app --reload --host 0.0.0.0 --port 8000`；
- 在 `frontend/` 启动 `pnpm dev`（Vite，默认 `0.0.0.0:5173`）；
- 捕获 `Ctrl+C`，同时停止两个进程。

启动后打开：

| 入口 | 地址 |
|---|---|
| 前端控制台 | <http://127.0.0.1:5173> |
| API 文档（Swagger） | <http://127.0.0.1:8000/docs> |
| 健康检查 | <http://127.0.0.1:8000/api/health> |
| 就绪检查 | <http://127.0.0.1:8000/api/health/ready> |

首次启动会自动创建 SQLite 数据库、建表并写入确定性种子数据，不需要手动迁移。

### 2.2 分开启动（推荐用于演示数据/排障）

终端 1，后端：

```bash
cd /home/lqz5885/aegisbank/dev/aegisbank/backend
AEGIS_DATABASE_PATH=/home/lqz5885/aegisbank/dev/aegisbank/backend/data/dogfood.db \
  uv run uvicorn aegisbank_api.main:app --reload --host 0.0.0.0 --port 8000
```

终端 2，前端：

```bash
cd /home/lqz5885/aegisbank/dev/aegisbank/frontend
pnpm dev
```

> `AEGIS_DATABASE_PATH` 建议始终使用**绝对路径**。原因见 §3.4：相对路径由后端进程的当前工作目录解析，而不是由仓库根目录解析；`$PWD` 又会在不同 shell、不同目录、Windows/WSL 传参时变化。
>
> 若尚未执行 §3 的 `seed-demo.sh`，`dogfood.db` 只会自动获得基础种子，**不含** 3000 元虚拟卡。

### 2.3 从 Windows PowerShell 启动

```powershell
wsl -d Ubuntu-24.04 -- bash -lc 'cd /home/lqz5885/aegisbank/dev/aegisbank && bash scripts/dev.sh'
```

保持该 PowerShell 窗口打开；`Ctrl+C` 会停止前后端。不要关闭 WSL 发行版或执行 `wsl --shutdown`，否则服务会中断。

### 2.4 用 `dev.sh` 指向演示数据库

如果希望一键启动时直接使用 `dogfood.db`（前提是已执行 §3 的 `seed-demo.sh`，含 3000 元虚拟卡），可以在启动前导出环境变量：

```bash
cd /home/lqz5885/aegisbank/dev/aegisbank
AEGIS_DATABASE_PATH=/home/lqz5885/aegisbank/dev/aegisbank/backend/data/dogfood.db \
  bash scripts/dev.sh
```

环境变量会被 `dev.sh` 启动的后端继承。前端不需要该变量。

### 2.5 停止与确认端口释放

优先使用 `Ctrl+C`。如果进程残留：

```bash
pkill -f "uvicorn aegisbank_api.main:app" || true
pkill -f "vite" || true
ss -ltnp | grep -E ':8000|:5173' || true
```

确认 8000 / 5173 没有监听后再重新启动，尤其是运行 `smoke.sh` 或切换数据库之前。

## 3. 演示数据

### 3.1 `seed-demo.sh` 做什么

```bash
cd /home/lqz5885/aegisbank/dev/aegisbank
bash scripts/seed-demo.sh
```

默认行为：

- 目标数据库：`backend/data/dogfood.db`（可用第一个参数覆盖）；
- 脚本调用 `uv run python -m aegisbank_api.demo_seed --db "$DB_PATH" --reset`；
- `--reset` 会删除目标数据库及其 `-wal` / `-shm` 文件；
- 重新写入基础 Mock Bank Core 种子；
- 额外植入一张 **3000 元虚拟卡**。

| 项目 | 值 |
|---|---|
| 虚拟卡账户 | `ACC-3003`「虚拟卡账户」 |
| 余额 / 可用余额 | **3000.00 元** |
| 虚拟卡 | `CARD-9001`（`**** 9001`，状态 active） |
| 开卡入金流水 | `TX-VCARD-001`（+3000 元，收入） |
| 演示用户 | `demo-user` |

> **默认库不是同一个**：`bash scripts/dev.sh` 默认使用 `backend/data/aegisbank.db`，而 `seed-demo.sh` 默认重置 `backend/data/dogfood.db`。要演示 3000 元虚拟卡，必须让后端指向 `dogfood.db`（或用 `seed-demo.sh` 显式重置 `aegisbank.db`）。

脚本结束后会打印启动提示；请用**同一个数据库路径**启动后端。

### 3.2 为什么重置前必须先停后端

`--reset` 会直接删除数据库文件及其 WAL/SHM 文件。如果后端仍在运行：

- SQLite 连接仍持有旧文件的句柄；在 Linux 上 `unlink` 后旧 inode 仍可能存活，后端继续读写旧库，而新库是另一个文件；
- 运行中的进程可能继续写 `-wal` / `-shm`，造成新旧文件不一致、锁冲突或 `database disk image is malformed`；
- 前端看到的仍是旧数据，重启后才发现数据“消失”或“回退”；
- 在 WSL / Windows 混合访问时，文件锁行为更不可预测。

正确顺序：

```bash
# 1. 停后端（Ctrl+C，或）
pkill -f "uvicorn aegisbank_api.main:app" || true

# 2. 确认端口释放
ss -ltnp | grep ':8000' || true

# 3. 重置并植入演示数据（绝对路径）
DB=/home/lqz5885/aegisbank/dev/aegisbank/backend/data/dogfood.db
bash scripts/seed-demo.sh "$DB"

# 4. 用同一个绝对路径启动后端
cd /home/lqz5885/aegisbank/dev/aegisbank/backend
AEGIS_DATABASE_PATH="$DB" \
  uv run uvicorn aegisbank_api.main:app --reload --host 0.0.0.0 --port 8000
```

前端可以继续运行；刷新页面即可看到新数据。

### 3.3 绝对路径示例

```bash
DB=/home/lqz5885/aegisbank/dev/aegisbank/backend/data/dogfood.db

bash scripts/seed-demo.sh "$DB"

cd /home/lqz5885/aegisbank/dev/aegisbank/backend
AEGIS_DATABASE_PATH="$DB" \
  uv run uvicorn aegisbank_api.main:app --reload --host 0.0.0.0 --port 8000
```

如果使用默认数据库（`backend/data/aegisbank.db`）并希望也带虚拟卡：

```bash
DB=/home/lqz5885/aegisbank/dev/aegisbank/backend/data/aegisbank.db
bash scripts/seed-demo.sh "$DB"
```

### 3.4 为什么不要用 `$PWD`（跨 shell 解析陷阱）

常见错误：

```bash
# 错误示例：在仓库根目录把 $PWD 当成 backend 目录
bash scripts/seed-demo.sh "$PWD/data/dogfood.db"
# 实际传给脚本的是 /repo/data/dogfood.db，而不是 /repo/backend/data/dogfood.db
```

另一个常见错误：

```bash
# 在一个 shell 里设置，在另一个 shell 里使用；或经过 sudo / IDE / Windows 包装后 $PWD 已变
DB=$PWD/data/dogfood.db
cd backend
AEGIS_DATABASE_PATH="$DB" uv run uvicorn ...
```

原因有三层：

1. **脚本默认路径相对仓库根**：`seed-demo.sh` 默认使用 `$ROOT/backend/data/dogfood.db`；
2. **后端配置相对进程工作目录**：`AEGIS_DATABASE_PATH` 是 `Path`，相对路径由启动 `uvicorn` 时的当前目录解析；在 `backend/` 下 `data/dogfood.db` 才对，在仓库根下就变成另一个文件；
3. **`$PWD` 在跨 shell / 跨平台传参时不可靠**：Windows PowerShell、WSL `bash -lc`、`sudo`、IDE 终端、CI 都可能在不同目录展开变量。

因此推荐写死一个绝对路径变量（如 §3.3），seed 与 uvicorn 使用同一个值。这样无论从哪个目录启动，都是同一个数据库。

### 3.5 验证演示数据

启动后端后：

```bash
# 概览：账户与卡片（overview 不返回完整流水）
curl -s http://127.0.0.1:8000/api/banking/overview

# 流水：显式调用 query_bill 查看 ACC-3003 的本月账单
curl -s -X POST http://127.0.0.1:8000/api/agent/run \
  -H 'Content-Type: application/json' \
  -d '{"instruction":"查询我的本月账单","tool_name":"query_bill","arguments":{"account_id":"ACC-3003"}}'
```

预期：

- `overview` 的 `accounts` 里 `account_id=ACC-3003`，`balance_cny=3000.0`；`cards` 里 `card_id=CARD-9001`；
- 显式 `query_bill` 的 `results[0].data.transactions` 中包含 `TX-VCARD-001`（+3000 元，收入）。

也可以在「01 银行概览」页面确认虚拟卡 `**** 9001` 与 3000 元余额。

### 3.6 重置与恢复干净状态

- 想恢复含虚拟卡的演示数据：停后端 → `bash scripts/seed-demo.sh /abs/path/dogfood.db` → 用同一路径启动；
- 想恢复基础种子（无虚拟卡）：停后端 → 删除目标库文件（含 `-wal`/`-shm`）→ 启动后端自动重建；
- 不要在运行中的后端上删除/覆盖数据库；不要把 `--reset` 指向任何真实或非演示数据库。

## 5. 配置项

### 5.1 配置加载方式

后端使用 `pydantic-settings`，前缀 `AEGIS_`：

- 配置文件默认读取**当前工作目录**下的 `.env`；从 `backend/` 启动时即 `backend/.env`；
- 推荐把根目录 `.env.example` 复制为 `backend/.env` 后修改；
- Shell 环境变量优先于 `.env`；
- 不要提交 `.env`、真实 API Key、真实银行凭据或客户数据。

```bash
cd /home/lqz5885/aegisbank/dev/aegisbank
cp .env.example backend/.env
# 按需编辑 backend/.env
```

| `AEGIS_SCENARIO_STRICT` | `1` | 场景加载失败是否报错 | `0` 时跳过失败模块并告警 |
| `AEGIS_EXTENSION_ALLOW` | 空（全部） | 只加载指定 2A 扩展 | 如 `mfa,sandbox`；`none` 关闭 |
| `AEGIS_EXTENSION_STRICT` | `1` | 扩展加载失败是否报错 | `0` 时容忍加载失败 |

> 场景/扩展开关不是核心配置项，读取位置在 `scenarios/__init__.py` 与 `extensions/__init__.py` 的自动发现逻辑中；用于并行开发与演示隔离。

## 7. 常见问题

### 7.1 端口被占用

**现象**：`Address already in use` / `EADDRINUSE`，或 `smoke.sh` 连到了旧服务。

```bash
ss -ltnp | grep -E ':8000|:5173' || true
pkill -f "uvicorn aegisbank_api.main:app" || true
pkill -f "vite" || true
```

确认释放后再启动。`smoke.sh` 会占用 8000，运行前先停 `dev.sh` 或单独启动的后端。若必须换端口：后端加 `--port 8001`，前端用 `pnpm dev -- --port 5174`，同时修改 `vite.config.ts` 的代理 target，并更新本文/演示脚本中的地址。

### 7.2 `uv` / `pnpm` / `node` 找不到

**现象**：`command not found`，或版本与预期不符。

```bash
bash -lc 'command -v uv pnpm node python3; uv --version; pnpm --version; node --version'
```

原因与处理：

- WSL 的非 login shell 没有加载 `~/.bashrc` / `~/.profile`，`~/.local/bin`、nvm、corepack 路径不在 PATH；使用 `bash -lc` 或在新终端登录，必要时执行 `export PATH="$HOME/.local/bin:$PATH"`；
- `uv` 未安装：用官方脚本安装后重新打开 shell：

  ```bash
  curl -LsSf https://astral.sh/uv/install.sh | sh
  source ~/.bashrc
  ```

- `pnpm` 未安装：`corepack enable`，或 `npm install -g pnpm`；
- 不要调用 Windows 的 `uv.exe` / `node.exe`；确认 `which uv`、`which node` 指向 Linux 路径；
- 安装后在仓库根执行 `bash scripts/bootstrap.sh`。

### 7.3 WSL 端口转发 / 浏览器打不开

**现象**：WSL 内 `curl` 正常，Windows 浏览器访问 `127.0.0.1:5173` 失败。

处理顺序：

1. 确认进程在跑：`ss -ltnp | grep -E ':5173|:8000'`；
2. WSL 内自测：`curl -s http://127.0.0.1:5173`、`curl -s http://127.0.0.1:8000/api/health`；
3. 浏览器试 `http://localhost:5173`（有些环境 localhost 与 127.0.0.1 转发行为不同）；
4. 在 Windows PowerShell 执行 `wsl --shutdown`，再重新打开 WSL 与 `dev.sh`；
5. 检查 Windows 防火墙是否拦截 WSL 的端口；
6. 仍不行时用 `wsl hostname -I` 获取 WSL IP 访问，或在 Windows 侧配置 portproxy（仅本地演示，不建议公网暴露）；
7. 确认没有把服务只绑定在 `127.0.0.1`（`dev.sh` 已绑定 `0.0.0.0`）。

### 7.4 数据库被占用 / 打不开 / malformed

**现象**：`database is locked`、`unable to open database file`、`database disk image is malformed`。

处理：

```bash
pkill -f "uvicorn aegisbank_api.main:app" || true
ls -la backend/data/
# 确认后端已停止后，才考虑删除演示库及其 -wal/-shm
```

- 最常见原因是重置数据库时后端还在运行（见 §3.2）；停后端后重新 `seed-demo.sh`；
- 不要手动编辑 SQLite 文件，也不要在后端运行时复制/覆盖数据库；
- 确认 `AEGIS_DATABASE_PATH` 指向的目录存在且当前用户可写；
- 演示环境可直接重置；生产数据必须走备份/恢复流程。

### 7.5 页面能打开，但写操作是灰的

**现象**：任务提交、确认、时间快进等按钮禁用，或接口返回 503。

原因通常是 readiness 非 `ready`：

```bash
curl -s http://127.0.0.1:8000/api/health/ready
```

- `sqlite` 不可用：检查数据库路径/权限/锁；
- `audit_chain` 断裂：检查审计链；演示环境可重置数据库，生产需从备份恢复并调查；
- `mock_bank_seed` 缺失：重新 `seed-demo.sh` 或让应用重建种子；
- `planner` 不可用：状态为 `degraded`，写操作仍会 503；检查 Planner 配置/依赖；
- 若当前角色是 `operator` 或 `auditor`，写操作也会被角色能力拒绝（不是 readiness 问题）；切回 `user` 或检查 `X-Aegis-Role`。

前端 `ReadinessBanner` 会展示各组件状态；非 `ready` 时禁用写操作是**预期的 fail-closed 行为**，不是 UI bug。

### 7.6 演示 OTP / 生物识别

- 红色操作默认 OTP：`246810`；
- 模拟生物识别：`FACE-888888`；
- 黄色操作只需确认，不需要 OTP；
- 错误 OTP 返回 403 并写 `mfa_failed` 审计；未知 provider 也返回 403；
- 演示 token 只用于本地，不得用于任何真实环境；
- 若修改 `AEGIS_DEMO_OTP`，确认命令/演示脚本/前端提示同步更新。

### 7.7 重置数据

```bash
cd /home/lqz5885/aegisbank/dev/aegisbank
pkill -f "uvicorn aegisbank_api.main:app" || true
DB=/home/lqz5885/aegisbank/dev/aegisbank/backend/data/dogfood.db
bash scripts/seed-demo.sh "$DB"
cd backend
AEGIS_DATABASE_PATH="$DB" uv run uvicorn aegisbank_api.main:app --reload --host 0.0.0.0 --port 8000
```

刷新前端即可。重置会清空审计记录、待确认动作、熔断状态、幂等键等；如只想清空业务数据但保留审计，需另写脚本，不在演示流程内。

### 7.8 CORS 错误

**现象**：浏览器控制台出现 `No 'Access-Control-Allow-Origin' header`。

- 优先使用 Vite 代理（前端相对 `/api`），开发期不直接跨域；
- 若直接从前端源码请求 `http://127.0.0.1:8000`，把前端 origin 加入 `AEGIS_CORS_ORIGINS`；
- 注意 `localhost` 与 `127.0.0.1` 不同；端口不同也不同；
- 修改后重启后端（CORS 中间件在启动时读取配置）。

### 7.9 LLM 配置失败

- 默认 `AEGIS_PLANNER_MODE=rule`，不依赖外部服务；如果不需要 LLM，保持 `rule`；
- `auto` 模式下 LLM 失败会回退规则 Planner，并在计划中标注 `planner: auto:rule-fallback`；
- `llm` 模式失败会报错，不会静默降级；
- 检查 `AEGIS_LLM_BASE_URL`、`AEGIS_LLM_MODEL`、`AEGIS_LLM_API_KEY`、网络与超时；
- 不要把真实客户数据发给外部模型；不要把 API Key 写入仓库或截图。

### 7.10 `smoke.sh` 失败

- 先停掉 `dev.sh` / 已占用 8000 的后端；
- 看脚本日志 `${TMPDIR:-/tmp}/aegisbank-smoke.log`；
- 确认 `uv` 可用、数据库目录可写；
- 若审计链失败，先看 `GET /api/audit/verify` 的 `broken_at`/`reason`；
- 演示环境可重置数据库后重跑。

### 7.11 审计链校验失败

- `GET /api/audit/verify` 返回 `valid=false` 时，先记录 `broken_at` 与 `reason`；
- 不要手工改审计表；演示环境可从干净数据库重建；
- 生产环境必须从备份恢复并调查篡改/损坏原因；
- 哈希链只能发现记录级变化，不能替代 WORM 与权限分离。

### 7.12 Windows 路径 / 换行符 / 权限问题

- 在 WSL ext4 上开发，不要在 `/mnt/d` 或 Windows 历史副本上运行；
- Shell 脚本需要 LF；如果从 Windows 复制导致 CRLF，执行 `sed -i 's/\r$//' scripts/*.sh`（仅修复换行，不改逻辑）；
- 不要在 WSL 内调用 Windows Python/Node；
- Git 操作建议在 WSL 内进行；推送可用 Windows 侧 git（见 README/AGENTS）。

## 8. 生产化部署差距

以下差距与 [`05-安全自评报告.md`](05-安全自评报告.md) §4 的 P0/P1/P2 风险对应。当前版本是本地演示原型，**不得**按本节之外的简化方式直接上生产。

| 领域 | 当前实现 | 生产化要求 |
|---|---|---|
| 真实凭据 / 密钥 | 无真实凭据；OTP 默认值在配置/代码中；LLM Key 走本地环境变量 | KMS/HSM/Vault；密钥轮换；最小权限；禁止代码默认值；审计密钥访问 |
| 传输安全 | 本地 HTTP | HTTPS/TLS；HSTS；内部 mTLS；证书管理；WAF/API 网关 |
| 身份认证 | 固定 `demo-user`；`X-Aegis-Role` 演示头 | OIDC/OAuth2 或银行统一认证；会话/Token；设备绑定；服务端角色推导；租户隔离 |
| 授权 | 静态角色矩阵 + 工具授权 | OPA/Cedar 等策略引擎；RBAC/ABAC；职责分离；审批流；定期复核 |
| MFA | 固定 OTP + 模拟生物识别 | 真实短信/TOTP/Passkey/U 盾/人脸；按用户挑战；失败锁定；限流；抗重放 |
| 审计存储 | 本地 SQLite + SHA-256 链 | 只追加/WORM；外部锚定/时间戳；SIEM；保留与销毁策略；权限分离；独立校验 |
| 沙箱隔离 | 进程内 socket/超时/体积/白名单 | 容器/微虚拟机；seccomp/AppArmor；cgroups；只读 FS；非 root；egress 策略；执行取消 |
| 数据库 / HA | SQLite 单机 | HA 数据库；备份/PITR；迁移；行级安全；静态加密；多副本；容量规划 |
| 幂等 / nonce | 单机表，无 TTL | 分布式存储 + TTL；唯一约束；跨进程锁；归档 |
| 熔断 | 系统级计数 | 按用户/租户分桶；分布式状态；告警；人工复核；限流 |
| 工具执行 | Python 线程，超时不能强杀 | 可取消 worker/队列；下游幂等；Saga/Outbox；对账；超时补偿 |
| IM 渠道 | 无平台签名；固定用户 | 平台签名校验；OAuth；真实用户映射；禁止消息内固定 OTP |
| 速率 / Web 安全 | 无速率限制、CSRF、CSP | API 限流/WAF；CSRF Token；CSP/安全头；依赖与供应链扫描 |
| 可观测性 | 本地日志与审计 | 结构化日志、指标、追踪、SLO、告警、审计看板 |
| 合规 | 未做等保/渗透/数据合规评审 | 威胁建模；渗透测试；依赖扫描；数据隐私影响评估；金融合规评审 |

```text

3. 依赖是否可用？        bash -lc 'uv --version; pnpm --version; node --version'

7. 再看日志与审计链      uvicorn 输出、/api/audit/verify
```
