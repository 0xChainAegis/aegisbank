## 1. 摘要与产品定位

银行 AI 智能体的真正难点不在「会不会聊天」，而在**高风险金融操作能不能被可信地控制**：模型不能编造金融事实、不能越权、不能把失败伪装成成功，用户确认的必须就是实际执行的那一笔，事后必须可验证地留痕。

AegisBank 因此不做「聊天机器人 + 几个银行函数」，而是给 Agent 增加一层**金融操作控制平面**：

```text
自然语言意图
  → 结构化 Planner（只生成计划，不执行工具；候选白名单）
  → 确定性 Plan Compiler（Schema / DAG / plan_hash）
  → 动态风险引擎（绿 / 黄 / 红 + 可解释原因，只升不降）
  → 统一权限网关（注入拦截 / 角色能力 / 最小权限 / 分级决策）
  → ActionEnvelope 绑定 + 分级确认 + 演示 MFA
  → ToolExecutor + ExecutionGuard（沙箱）→ Mock Bank Core 工具
  → SHA-256 审计哈希链 + 证据分层
```

交付内容：6 个业务场景（转账、账单、理财、卡片、订阅、跨场景联动）、50 个工具、49 个 HTTP 接口、187 项后端测试、53 项前端测试、29 项六场景端到端回归。

### 3.3 端到端数据流（以「转账 880 元」为例）

1. **指令**：用户输入「向 ACC-2002 转账 880 元」。
2. **规划**：Planner 产出 `ExecutionPlan`（`transfer` 步骤，参数 only）。
3. **编译**：Compiler 校验工具/参数/DAG，生成规范化 `plan_hash`。
4. **风控**：动态风险引擎评估金额与当日累计 → 黄色（≤1000 元且单笔 ≤5000 元）。
5. **网关**：注入扫描 → 角色能力 → 工具授权 → 分级决策 = `confirm`。
6. **确认**：服务端签发 `ActionEnvelope`（plan/args hash + nonce + expires_at），前端弹确认。
7. **复核执行**：用户确认后重算哈希/风险/权限，校验 nonce 与过期；一致则经 `ToolExecutor` 执行工具，不一致返回 409 且不执行。
8. **审计**：写入六字段 + 四类证据 + 哈希链，返回回执与可回放审计。

## 4. 核心机制与算法

### 4.1 意图规划（不猜测、可澄清、可回退）

- **三种 Planner**：`rule`（确定性、离线可用、默认）、`llm`（OpenAI-compatible，严格结构化输出）、`auto`（LLM 失败自动回退 rule 并显式标记）。
- **澄清优先**：缺金额/收款方/订阅目标/生日对象时返回 `needs_clarification`，不猜测；多命中（如多个理财产品或联系人）列出候选让用户选择。
- **模型候选白名单**：模型输出只接受 `ExecutionPlan` 契约字段；不得覆盖用户显式给出的账户/金额；不得补全用户未提供的收款方；冲突转澄清。
- **场景意图扩展**：每个场景模块通过 `IntentRule` 注册意图（如「取消异常订阅」「买 1000 元稳健短债A」「帮我准备下个月妈妈的生日」），按优先级在核心规则之前匹配，不命中则交回核心链路。

### 4.2 Plan Compiler 与 plan_hash

```text
校验：工具必须已注册；参数必须通过工具 input_schema；步骤 id 唯一；
      依赖存在且无自环；DAG 无环；单计划 ≤12 节点；needs_clarification 不得执行。
编译：拓扑排序 → 规范化节点顺序 → sha256(canonical_json({intent, steps}))
```

`plan_hash` 在确认前签发、执行前**重新计算**；参数任何变化都会导致哈希不一致 → `409 ENVELOPE_MISMATCH`，不执行、不写业务审计。

### 4.3 动态风险（只升不降）

| 等级 | 含义 | 判定示例 | 系统行为 |
|---|---|---|---|
| 🟢 绿 | 只读查询 | 账单/余额/持仓/订阅查询、报告、异常检测 | 最小权限满足后直接执行 |
| 🟡 黄 | 修改设置或小额动账 | 单笔转账 ≤5000 且当日累计 ≤1000；改还款日/限额/额度 ≤5000；取消订阅；理财赎回 ≤1000 | 5 分钟内人工确认 |
| 🔴 红 | 资金变动/账户安全 | 单笔 >5000 或当日累计 >1000；挂失/解挂/改密码；理财申购；大额赎回 | 确认 + 二次身份校验（OTP/模拟生物识别） |

规则位于 `risk.py`（核心工具）与各场景 `risk_rules()`（场景工具），引擎只允许保持或上调工具基线风险，**任何模型输出都不得降低风险等级**。

### 4.4 统一权限网关（唯一入口）

`gateway.evaluate()` 的检查顺序：

1. **注入扫描**：instruction + arguments 命中规则 → `deny`（并在 Planner 之前整条拒绝，见 4.5）；
2. **角色能力**：`AuthzService.allowed(role, "tool:execute")`，仅 `user` 可执行银行工具；
3. **工具授权**：`permissions.is_granted(user_id, tool_name)`，撤权立即生效；
4. **分级决策**：绿 → `allow`；黄/红 → `confirm`（红附带 `requires_reauth=True`）。

任一节点被拒绝 → 整条 DAG 阻断（不执行后续节点），并记录 `gateway_blocked` 审计。

### 4.5 ActionEnvelope、幂等与注入

**ActionEnvelope/v1**（`trust/action_envelope.py`）字段：

```text
schema_version / user_id / plan_hash / step_id / tool_name / arguments_hash
/ risk_level / risk_reasons / permission / nonce / issued_at / expires_at
/ confirmation_state / approval_token
```

- 用户确认的是**这份 envelope**；执行前服务端重算 `plan_hash`、`arguments_hash`、风险与权限，任一不一致 → `409 ENVELOPE_MISMATCH`；过期 → `409 ENVELOPE_EXPIRED`；nonce 复用 → `409 NONCE_REUSED`。
- **幂等**：`/api/agent/run`、`/api/confirmations/{id}` 支持 `Idempotency-Key`。同键同体返回首次结果、不再产生第二笔；同键异体 → 409；重复确认返回首次结果，不会重复执行。
- **注入整条拒绝**：`scheduler.run` 在进入 Planner 之前扫描，命中即拒绝，响应不含可执行计划，审计记录 `injection_blocked` 与命中规则。

### 4.6 状态机与 UNKNOWN

```text
DRAFT → AWAITING_CONFIRMATION → AWAITING_REAUTH → APPROVED → EXECUTING
   ├→ COMPLETED / FAILED
   ├→ PAUSED → EXECUTING / ROLLED_BACK
   └→ UNKNOWN → RECONCILED / ROLLED_BACK
REJECTED / EXPIRED / BLOCKED 为分支终态
```

- 所有迁移写审计；非法迁移被拒绝（`state_transition_rejected`）。
- `UNKNOWN`：执行已发出但结果不确定，**不得自动重复下单**，需人工对账（`POST /api/trust/actions/{id}/reconcile`）。

### 4.7 步骤级暂停 / 回退 / 补偿（2A）

- **声明**：工具用 `ToolMetadata.compensable / compensation_tool` 声明可逆性；`compensation.py` 登记 28 条补偿规格（15 可补偿 / 13 不可逆）。
- **暂停**：调度器在节点之间检查 `action_id` 暂停登记，命中即停并返回 `status=paused`（含已执行结果、剩余步骤、恢复入口）。
- **补偿**：多步 DAG 中途失败时，对已成功且可逆的节点**逆序**执行补偿工具。补偿同样经 `gateway.evaluate`（权限/角色/风险）复检、经 `ToolExecutor` 执行，并写 `compensation_executed / compensation_failed` 审计。
- **状态**：全部补偿成功 → `rolled_back`；部分失败 → `unknown`（人工介入）；存在已执行的不可逆步骤 → 阻止回滚并明确标注「不可撤销」。
- 端点：`POST /api/actions/{id}/pause|resume|rollback`、`GET /api/actions/{id}/journal`、`GET /api/compensation/specs`。

### 4.8 可疑行为熔断（2A）

| 规则 | 阈值 | 窗口 | 说明 |
|---|---|---|---|
| 连续工具失败 | 3 次 | 60s | 阶段 1 语义 |
| 短时多次红色操作 | 3 次 | 300s | 仅 red 计数 |
| 注入命中累计 | 3 次 | 300s | 命中即累计 |

三类规则共用同一 open 状态与锁定时间；触发后写操作统一拒绝并给出可读原因（含「执行熔断已触发」与恢复方式）。operator 可在运维面板解锁（写 `circuit_breaker_unlock` 审计）。

### 4.9 演示 MFA Provider（2A）

- `trust/mfa.py`：`MfaProvider` 协议 + `OtpProvider`（演示 `246810`）+ `SimulatedBiometricProvider`（演示 `FACE-888888`，标注模拟人脸/设备确认）+ `MfaPolicy`（按工具/风险给出允许 provider 与默认）。
- 调度器确认时调用 `self.mfa.verify(token, provider=mfa_provider)`；成功/失败分别写 `confirmation_approved.mfa` 与 `mfa_failed` 审计（provider / verification_kind / result）。
- 端点：`GET /api/mfa/providers`、`GET /api/mfa/policy`、`POST /api/mfa/demo/challenge`。

### 4.10 工具沙箱（2A）

- 所有工具执行统一走 `executor.ToolExecutor`；`ExecutionGuard` 在前后钩子中实现沙箱。
- `trust/sandbox.py`：超时（线程 + future timeout）、网络阻断（拦截 socket connect/getaddrinfo 等）、入参/输出体积上限、可选工具白名单；违规先写 `sandbox_blocked`/`sandbox_timeout` 审计再抛 `SandboxViolation`。
- **诚实边界**：进程内演示级沙箱，不是 OS 容器/命名空间隔离；Python 线程无法强杀；生产需容器化或独立执行沙箱。

### 4.11 IM 渠道适配器（2A）

- `channels/im.py`：IM/CLI/webhook 消息 → 复用同一 `scheduler.run`；文本 `确认 {action_id} 验证码 {otp}` → 复用确认链路。
- `message_id` 幂等：命中 `im_messages` 直接回放首次回执；审计 `im_message_executed / im_message_rejected`。
- 端点：`POST /api/channels/im/message`、`GET /api/channels/im/help`。

### 4.12 多角色与撤权（2A）

| 角色 | 能力 | 用途 |
|---|---|---|
| user | tool:execute / permission:manage / audit:read / trust:inspect | 普通客户，可发起银行任务 |
| operator | ops:manage / trust:inspect / audit:read / permission:manage | 运维：熔断解锁、状态查看；**不能执行银行工具** |
| auditor | audit:read / trust:inspect | 只读审计视角 |

角色通过演示请求头 `X-Aegis-Role` 解析（`AuthzService` 统一能力口径，禁止在扩展/前端硬编码）。撤权（`PUT /api/permissions/{tool}`、`POST /api/authz/revoke/{tool}`）立即生效，待确认动作在执行前会被网关复检拦截。

### 4.13 审计与证据分层

- **六字段**：触发时间、原始指令、DAG 路径、工具入参、执行结果、用户确认状态。
- **哈希链**：`entry_hash = SHA-256(prev_hash + canonical(entry))`；`GET /api/audit/verify` 返回 `{valid, checked}`。
- **证据分层**：`source ∈ {mock_bank, human_confirmation, policy_engine, audit_chain}`、`verified`、`verification_kind ∈ {tool_result, approval, policy_decision, hash_chain}`；写入审计 `result_json` 并参与链计算，前端与回执均可展示。

| 智能转账 | `从 ACC-3003 向 ACC-2002 转账 500 元` / `给妈妈转 500` / `和妈妈、张三 AA 300` | `transfer`、`transfer_to_contact`、联系人簿、AA 并行 DAG | 黄→红（累计>1000） |

| 理财操作 | `有什么理财产品` / `买 1000 元稳健短债A` / `我的理财持仓` / `赎回 500 元` | `list_wealth_products`、`query_wealth_holdings`、`assess_wealth_risk`、`purchase_wealth`、`redeem_wealth` | 申购红；赎回黄/红按金额 |
| 跨场景联动 | `分析我的账单并取消异常订阅` / `帮我准备下个月妈妈的生日，预算 1000 元` / `下周三给张三转 500` + 时间快进 | 两步 DAG、生日 4 步 DAG、`schedule_transfer`、`run_due_tasks` | 黄（DAG 取最高风险） |

场景以「模块即场景」方式自动发现（`scenarios/README.md` 契约），新增场景只需新增一个模块文件 + 测试，核心装配零改动。

### 6.2 关键工程取舍

1. **模块自动发现**：场景与 2A 能力均为「加一个文件」扩展，避免核心文件膨胀；支持 `AEGIS_SCENARIO_ALLOW` / `AEGIS_EXTENSION_ALLOW` 隔离并行开发与演示。
2. **统一执行器**：所有工具执行只有一个入口，沙箱/审计/超时都挂在这一条链上，避免绕过。
3. **补偿经网关**：回滚不是"再跑一次工具"，而是重新经过权限/角色/风险复检并写审计，保证失败路径同样可信。
4. **时间维度**：`scheduled_tasks` + `run_due_tasks` + `POST /api/automation/run-due?now=` 时间快进；复用同一状态机/幂等/审计（不做第二套调度器）。

## 8. 安全边界与生产化差距

- **数据边界**：全部为 Mock Bank Core 模拟数据，不连接真实银行、不产生真实资金；理财不构成投资建议。
- **身份边界**：无登录/会话/设备指纹，演示固定用户；`X-Aegis-Role` 是演示头，不是认证。
- **MFA 边界**：OTP 固定值、生物识别为模拟，仅本地演示。
- **沙箱边界**：进程内守卫（超时/网络/体积/白名单），非 OS 级隔离；线程超时不能强杀。
- **存储边界**：SQLite 单机，无高可用/容灾/WORM；幂等键与 nonce 无 TTL。
- **熔断边界**：系统级计数而非按用户；可疑规则为确定性演示策略。
- **上下文边界**：已支持限时、单次消费的澄清续问；通用指代与长会话尚未实现；复杂省略表达会转澄清。
- **生产化清单**：真实身份接入、HTTPS、真实 MFA Provider、IM 平台签名与用户映射、OS 级沙箱、审计 WORM 存储、幂等/nonce TTL、按用户熔断、真实常驻调度。

> 六场景「完整覆盖」指：典型能力可用自然语言发起、分级正确、审计可见、前端可展示；不等于生产业务完整性。
